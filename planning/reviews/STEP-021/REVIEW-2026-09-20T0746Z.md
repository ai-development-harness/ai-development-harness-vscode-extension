## Findings

### F-001 — High — debounce wiring is not proved at the actual provider boundary

**Location:** `src/editor/activation.ts`; `tests/unit/editor/activation.test.ts`.

`ValidationController` is covered in isolation, but no regression drives
`registerStepEditor` through `onDidChangeTextDocument` and observes diagnostic
publication. A future direct full validation on every change, or an unconnected
controller, could pass the current tests. Add a deterministic wiring seam that
proves debounce, latest-only publication and disposal at the diagnostics path.

### F-002 — Medium — grammar test does not prove Markdown tokenization

**Location:** `tests/unit/editor/activation.test.ts`.

The structural assertion for `include: "text.html.markdown"` confirms intended
composition but not its behavior in the actual VS Code grammar registry. It does
not prove fenced code, links, emphasis, inline code and lists retain Markdown
scopes. Add a focused Extension Host/tokenization regression, or document a
demonstrated unavailable public seam as a concrete blocker; do not treat JSON
shape alone as acceptance evidence.

### F-003 — Medium — custom taskDirectory watcher refresh is not covered

**Location:** `src/editor/activation.ts`; `tests/unit/editor/activation.test.ts`.

The test calls `loadIndex` with a custom manifest directory, but does not prove
watcher/provider refresh uses the same manifest-resolved directory. A regression
that hardcodes the watcher path could remain green. Cover the watcher pattern or
an equivalent observable refresh behavior for a relocated `taskDirectory`.

### F-004 — Low — per-document debounce behavior lacks a regression

**Location:** `src/editor/activation.ts`; `tests/unit/editor/activation.test.ts`.

The implementation maintains controllers by URI, but tests do not prove that
independent pending validations for two documents both run. Add a focused test
or incorporate this case in the provider wiring regression.
