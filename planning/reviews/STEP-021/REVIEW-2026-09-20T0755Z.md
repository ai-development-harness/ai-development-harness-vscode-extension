## Closure предыдущих findings

### F-001 — Closed

`registerValidationListeners` теперь является отдельной production seam между
VS Code document events, per-document scheduler и `DiagnosticCollection`.
Regression вызывает фактические change/close callbacks, доказывает debounce,
latest-only publication и отсутствие публикации после close. В
`registerStepEditor` эта seam подключена к тому же `DocumentValidationScheduler`,
который вызывает реальный `validateStepDocument` и публикует diagnostics.

### F-002 — Closed с документированным platform constraint

Grammar добавляет `text.html.markdown` последним base include, сохраняя
приоритет Harness-specific rules без копирования стандартной Markdown grammar.
Structural regression проверяет include и порядок правил, а Extension
Development Host успешно загружает `harness-step`.

Отсутствие прямого assertion TextMate scopes обосновано: публичные typings VS
Code 1.138 не предоставляют grammar registry/token-scope API. Официальная
документация описывает grammar contribution и интерактивный
`Developer: Inspect Editor Tokens and Scopes`, но не программный API чтения
TextMate scopes. Ограничение явно записано в `docs/architecture.md`; internal
API, vendored Markdown grammar и новая test dependency не введены.

### F-003 — Closed

`stepEditorWatchPatterns(manifest)` строит STEP glob только из
`manifest.protocol.taskDirectory`. Regression с `custom/steps` проверяет и
положительный custom pattern, и отсутствие `planning/tasks` в runtime watcher
patterns. Runtime selector остаётся language-only; неизбежный static
`filenamePatterns` локализован в declarative contribution и документирован.

### F-004 — Closed

Event-boundary regression ставит pending validation для двух URI и доказывает,
что оба документа публикуются независимо, тогда как повторные изменения одного
URI объединяются до последнего текста.
