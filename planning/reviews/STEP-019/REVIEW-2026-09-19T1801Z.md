## Findings

### F-001 — High — Нет обязательной capability matrix, а часть primary evidence невоспроизводима

**Location:** `planning/tasks/STEP-019.md:43-44,72,79-80,103-107,121-124`;
`docs/adr/ADR-010-manual-agent-handoff-mvp.md:16-21,48-58,90-100`.

**Scenario:** STEP требует для каждой рассмотренной
executor/platform combination отдельные evidence и verdict по пяти
критериям. ADR-010 даёт только общий вывод: для Codex названы
sandbox и structured output, для Claude — только отсутствие sandbox
на native Windows. Нет строк Codex/macOS, Codex/Linux, Codex/WSL2,
Codex/native Windows, Claude/macOS, Claude/Linux, Claude/WSL2 и Claude/native
Windows с verdict `AVAILABLE`/`UNAVAILABLE`/`UNVERIFIED` по каждому
критерию.

При этом обе OpenAI ссылки из ADR-010 после redirect возвращают
HTTP 404. Актуальная primary documentation дополнительно требует
более точной оценки: [OpenAI Sandbox](https://learn.chatgpt.com/docs/sandboxing)
описывает platform-native enforcement, inherited boundaries spawned commands и
writable roots; [Claude sandbox](https://code.claude.com/docs/en/sandboxing)
описывает OS-enforced `denyRead`/`allowRead`/`allowWrite` для
Bash/PowerShell/Monitor и их child processes на macOS/Linux/WSL2. Эти
свойства не доказывают containment detached descendants при cancel,
но их нельзя подменять кратким утверждением о permission modes.

**Impact:** без matrix нельзя воспроизвести главный вывод STEP
и отличить доказанную capability от недоказанной. Manual-only
решение fail-closed и само по себе безопасно, но Acceptance и
Verification STEP-019 не доказаны; будущий ADR не имеет
проверяемого baseline.

**Fix direction:** добавить в ADR-010 или ссылочный persisted evidence
явную executor/platform × five-criteria matrix. Для каждой ячейки
указать verdict, точную primary source/версию либо reproducible
evidence; недоказанные cancellation/environment criteria пометить
`UNVERIFIED`, а native Windows Claude — `UNAVAILABLE`. Исправить
OpenAI links и не приписывать source незафиксированные свойства.

### F-002 — High — Architecture baseline одновременно разрешает и запрещает automatic lifecycle

**Location:** `docs/architecture.md:7,12-13,22,26,38,43,62-70`;
`docs/adr/ADR-010-manual-agent-handoff-mvp.md:31-44`;
`docs/requirements/SPEC.md:139-160`.

**Scenario:** ADR-010 и REQ-005 запрещают любой automatic agent lifecycle в
MVP. `docs/architecture.md:43,64-65` повторяет этот запрет, но
тот же current architecture baseline выбирает headless CLI transport в System
context, описывает `Agent integration layer` как вызов агента, оставляет
watcher rationale на external headless writes и прямо посылает
read-only command в automatic executor с context bundle. External integration
дополнительно говорит, что extension передаёт prompt через stdin.

**Impact:** разработчик, следующий `Основным потокам` и component
boundary, может корректно сохранить/вернуть automatic read-only spawn,
хотя active ADR запрещает его. Это architecture drift на точной
security boundary, которую STEP-019 должен был сделать однозначной.

**Fix direction:** синхронизировать все current-state sections
`docs/architecture.md` с ADR-010: после pre-validation и read-only, и mutating
agent commands завершаются manual handoff без context bundle, stdin
и child process. Историческую/implemented адаптерную поверхность
описать отдельно как inactive drift, который удаляет/согласует
`STEP FIX STEP-009`, а не как активный поток MVP.

### F-003 — Medium — Manual fallback выводит free-text command без sanitization

**Location:** `src/commands/baseCommand.ts:40-51`;
`src/api/agentDispatcher.ts:94-96`; `src/locales/ru.json:29`;
`src/locales/en.json:29`; `docs/requirements/SPEC.md:153-154`.

**Scenario:** для `STEP ADD: <text>` и `PROJECT QUICK FIX: <text>` Command layer
склеивает user-controlled `freeText` с canonical prefix. Write policy возвращает
эту строку как `policy.command`, а `manualWriteFallback()` без
`sanitizeExternalText()` пишет её в Output Channel и передаёт в notification.
Например, input с `Authorization: Bearer <value>` будет показан
целиком; control/newline content также не проходит единую output
sanitization boundary.

**Impact:** фактический manual handoff нарушает новый REQ-005,
который явно запрещает secret values в Output Channel/notification. Также
возможна log/UI injection переносами строк и control characters.

**Fix direction:** production remediation не входит в document-only
Mutation policy STEP-019. Передать finding в уже запланированный
`STEP FIX STEP-009`: пропускать canonical command через единую
bounded redaction/control-character sanitization до Output Channel и i18n params,
не теряя канонический синтакс. Добавить unit/integration regression
с secret-shaped free text, CR/LF и ANSI/control characters.
