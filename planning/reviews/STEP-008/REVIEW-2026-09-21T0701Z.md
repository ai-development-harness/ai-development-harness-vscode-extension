## Findings

### F-001 — High — next item показывает внутренний command id вместо canonical command

**Location:** `src/ui/statusBar.ts:45`

Для выбранного STEP item показывает, например, `STEP-008: harness.implement`.
`harness.implement` — внутренний VS Code command id, а не рекомендуемая команда
Harness (`STEP IMPLEMENT STEP-008`), которую требует REQ-004 и которую ожидал
предыдущий finding F-002. В результате постоянно видимый индикатор не сообщает
пользователю фактическую next command.

**Fix direction:** переиспользовать результат `selectNextStep`, но отображать
соответствующую canonical command с target STEP; внутренний command id оставить
только в click action. Добавить regression для PLAN/FIX/IMPLEMENT и empty state.

### F-002 — Medium — artifact watcher disposables накапливаются при каждом refresh

**Location:** `src/ui/statusBar.ts:49`

`attachArtifactWatchers()` dispose-ит прежние элементы, но не очищает
`artifactWatchers`, после чего добавляет новый набор watcher/listener handles.
Каждое filesystem/diagnostic/language обновление увеличивает массив, а следующий
refresh повторно обходит всю историю уже disposed handles. При длительной работе
это даёт неограниченный рост retained objects и стоимость refresh.

Кроме того, manifest watcher на `src/ui/statusBar.ts:33-34` подписан только на
`onDidChange`: delete/create или atomic replacement manifest может оставить
Status Bar со старым состоянием.

**Fix direction:** atomically dispose и очистить старый набор перед созданием
нового либо reattach только при изменении topology; подписать manifest watcher
на create/change/delete. Покрыть повторный refresh и manifest replacement.

### F-003 — Medium — invalid manifest может опубликовать UI после dispose

**Location:** `src/ui/statusBar.ts:38-40`

После ожидания `parseManifest()` ветка invalid/uninitialized меняет четыре
StatusBarItem до проверки `this.disposed`. Если extension деактивирован во время
I/O, завершившийся refresh всё ещё публикует состояние в disposed items. Поэтому
предыдущий F-004 закрыт не полностью.

**Fix direction:** проверять актуальность/disposed сразу после каждого `await`,
до любой публикации, либо передавать generation token в refresh. Добавить тест с
deferred parse/refresh и dispose.

### F-004 — Medium — тесты не доказывают Status Bar contract и исправления review

**Location:** `tests/unit/ui/statusBar.test.ts:1-25`

Два теста проверяют только timer до запуска refresh. Нет тестов controller или
derived state для `initialized: false`, percentage, canonical recommendation и
click action, diagnostics filtering, watcher rebinding, overlap и dispose во
время активного refresh. Запланированный Extension Host regression из
`planning/tasks/STEP-008.md` отсутствует; существующие 27 integration tests не
содержат Status Bar assertions. Поэтому user-visible acceptance «видим,
обновляется, каждый клик выполняет заявленное действие» не имеет regression
evidence, а F-001—F-003 остаются незамеченными suite.

**Fix direction:** добавить pure derived-state seam и unit tests для состояний,
плюс Extension Host/controller regression для registration, external file
refresh и command wiring.
