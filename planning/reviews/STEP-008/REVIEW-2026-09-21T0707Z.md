### F-001 — Medium — regression suite не доказывает основной Status Bar contract

**Location:** `tests/unit/ui/statusBar.test.ts:1-35`, `tests/integration/`

Focused suite содержит два теста timer-а и три табличных case чистого
`canonicalNextCommand()`. Ни один тест не создаёт `HarnessStatusBar` и не
проверяет:

- `project.initialized: false` и invalid manifest;
- percentage, recommendation/empty state и реальные click commands;
- ограничение diagnostics canonical task directory;
- create/change/delete manifest и rebind artifact watchers;
- refresh при внешней правке STEP;
- dispose во время активного async refresh.

Запланированный в STEP Extension Host regression для registration, visibility и
external-file refresh отсутствует: текущий integration run содержит прежние 27
тестов и ни одного Status Bar suite/assertion. Поэтому зелёные gates доказывают
активацию расширения в целом, но не acceptance REQ-004 «элементы видны и
обновляются» и «клик по каждому элементу выполняет заявленное действие».

**Impact:** исправленные lifecycle и UI-сценарии могут регрессировать без падения
CI; текущий review не имеет независимого evidence для ключевого user-visible
поведения.

**Fix direction:** добавить test seam для состояния/items/watchers и unit tests
перечисленных веток, а также Extension Host regression для регистрации,
внешнего изменения STEP после debounce и command wiring. Не подменять это
проверкой formatter-а или общей активации extension.
