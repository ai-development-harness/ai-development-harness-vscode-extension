## Findings

### F-001 — Medium — custom taskDirectory не включён в diagnostics filtering regression

**Location:** `tests/integration/editor.test.js:57-99`

Тест очищает diagnostic collection до изменения manifest. После переключения
`protocol.taskDirectory` на `planning/custom-tasks` он проверяет только custom
STATUS URI и refresh от создания STEP. Diagnostics в custom directory не
публикуются, а control diagnostic в прежнем default `planning/tasks` не
проверяется.

Поэтому regression останется зелёным, если watcher и completion action успешно
перейдут на custom paths, но warning filter продолжит считать старый default
каталог. Это прямой контракт уточнённого REQ-004: Error/Warning должны
фильтроваться по текущему manifest-resolved task directory.

**Impact:** проект с custom Harness layout может показывать нулевой/чужой
warnings count при полностью зелёном suite.

**Fix direction:** после manifest switch создать Error/Warning diagnostic для
URI внутри custom task directory и control Error для URI в прежнем default
task directory; bounded polling должен доказать count только custom diagnostic.
После cleanup дождаться возврата исходного warning state.
