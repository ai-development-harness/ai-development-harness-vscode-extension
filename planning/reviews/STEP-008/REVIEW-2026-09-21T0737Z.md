## Findings

### F-001 — High — external refresh regression воспроизводимо нестабилен

**Location:** `tests/integration/editor.test.js:21-31`

Тест использует фиксированный `setTimeout(1300)` как proxy готовности watcher +
1000 ms scheduler + filesystem/Extension Host latency. В отдельном
последовательном прогоне к моменту assertion completion ещё не обновился, и suite
упал. Это тот же пользовательский путь, который должен доказывать REQ-004:
внешняя правка файла приводит к обновлению Status Bar после debounce.

**Impact:** CI и независимый review получают недетерминированный результат, а
acceptance внешнего refresh нельзя считать доказанным. Flake может скрывать как
медленную доставку watcher event, так и реальный пропуск refresh.

**Fix direction:** заменить fixed delay на bounded polling конкретного нового
состояния с диагностичным timeout; обеспечить cleanup и ожидание delete-refresh,
чтобы test не оставлял pending watcher работу следующим cases. Затем повторить
integration suite последовательно несколько раз.

### F-002 — Medium — exact click targets/actions всё ещё проверены не полностью

**Location:** `tests/integration/editor.test.js:17-31`

Finding F-001 отчёта `REVIEW-2026-09-21T0734Z.md` остаётся актуальным:
arguments initialization/completion не сверяются с exact manifest/STATUS URI, а
next action допускает любой command с prefix `harness.` вместо ожидаемого exact
command ID для controlled fixture.

**Impact:** неверный file target или неверная STEP action не уронят regression,
несмотря на click-action acceptance REQ-004.

**Fix direction:** после стабилизации ожидания проверить exact URI arguments и
exact next command ID вместе с `['STEP-998']`.
