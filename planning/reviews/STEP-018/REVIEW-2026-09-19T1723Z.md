## Findings

### F-001 — Medium (architecture/security traceability) — corrective STEP-009 всё ещё направлен на superseded environment allowlist

**Location:** `planning/tasks/STEP-009.md:12-17,370-378`,
`docs/requirements/SPEC.md:153-155`, `docs/architecture.md:59-64`,
`docs/adr/ADR-008-headless-agent-write-boundary.md:5-7,44-49`,
`docs/adr/ADR-009-user-managed-agent-cli-authentication.md:5-6,43-52`.

ADR-009 корректно supersedes пункт 4 ADR-008, но двусторонняя traceability и
handoff не синхронизированы. STEP-009 не перечисляет ADR-009 и его последнее
persisted corrective evidence по-прежнему требует per-executor
auth/provider/proxy/certificate allowlist. REQ-005 перечисляет STEP-018, но в
ADR-списке не содержит ADR-009. Architecture debt утверждает, что allowlist уже
реализован, не обозначая его как drift, который следующий FIX обязан удалить.
Наконец, ADR-008 одновременно сохраняет `Superseded by: —` и active-looking
пункт 4, хотя ADR index и ADR-009 говорят об узком supersession.

**Scenario:** следующий `STEP FIX STEP-009` восстанавливает контракт из своего
task и актуального FAIL review `17:08Z`. Агент расширяет environment allowlist
для Codex/Claude, чтобы закрыть F-004 этого review, то есть усиливает именно тот
контракт передачи credential/provider values, который ADR-009 уже запретил.

**Impact:** active architecture decision может быть нарушено корректным по
локальному task/handoff действием. Extension снова получает ответственность за
передачу secrets, а решение пользователя о user-managed CLI authentication не
становится исполнимым source of truth.

**Fix direction:** добавить ADR-009 в ADR-раздел и corrective handoff STEP-009;
заменить F-004/allowlist direction на удаление credential/provider/proxy/
certificate variables и тесты их явного отсутствия; добавить ADR-009 в
REQ-005 traceability; в architecture debt явно назвать текущий allowlist drift.
В ADR-008 обновить только историческую metadata-ссылку `Superseded by` на
ADR-009 с уточнением «Decision пункт 4», не переписывая исходный Decision.

**Security regression direction:** table-driven test для обоих executor'ов:
credential/provider/proxy/certificate и unrelated secret values отсутствуют в
child environment, допустимые platform-home/runtime values остаются; ни имя,
ни значение secret не попадают в Output Channel/UI/evidence.
