## Findings

### F-001 — Medium — Watcher не инвалидирует уже показанные CodeLens

**Location:** `src/editor/activation.ts:39-48,67`;
`tests/integration/editor.test.js:120-143`.

**Scenario:** Given открыт STEP с существующей ссылкой на отсутствующий ADR или
REQ, when внешний agent/CLI создаёт target-файл и watcher обновляет `index`,
then diagnostics, autocomplete и Definition Provider используют новый index,
но уже показанные CodeLens не пересчитываются. Обратный сценарий с внешним
удалением оставляет видимый устаревший lens, команда которого затем ничего не
открывает. Provider зарегистрирован только с `provideCodeLenses`; event
`onDidChangeCodeLenses`, предназначенный VSCode для уведомления об изменении
lenses, отсутствует. Изменение unrelated target-файла само не меняет открытый
STEP-документ.

**Impact:** внешний Harness-flow частично закрывает F-003, но UI остаётся
несогласованным: diagnostic может исчезнуть и Definition Provider уже начинает
работать, а обещанный REQ/ADR CodeLens не появляется до изменения либо
переоткрытия STEP. После удаления target пользователь видит неработающую
кликабельную ссылку. Это нарушает актуальность smart-editor surface на том же
watcher path, который введён для внешних изменений.

**Fix direction:** зарегистрировать CodeLensProvider с `EventEmitter<void>` и
вызывать его после успешной замены index (включая refresh после manifest path
change); emitter добавить в subscriptions. Regression должен держать STEP
открытым, внешне создать/удалить REQ/ADR target и доказать обновление CodeLens
без редактирования/reopen исходного STEP. Текущий watcher-тест проверяет только
completion и Definition Provider, поэтому этот presentation cache не покрыт.
