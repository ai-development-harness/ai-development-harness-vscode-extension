## Findings

### F-001 — Medium — Перекрывающиеся refresh могут вернуть устаревший index после более нового

**Location:** `src/editor/activation.ts:30-44,77-86`;
`tests/unit/editor/activation.test.ts:3-58`.

**Scenario:** Given refresh A уже вышел из debounce и читает старое состояние
workspace, when следующий watcher event планирует refresh B во время
незавершённого A, then controller запускает B параллельно. Если B первым
завершает чтение нового состояния, callback сразу присваивает новые
`manifest`/`index`. Когда A завершается позже, его callback повторно присваивает
устаревшие данные и публикует ещё одну CodeLens invalidation. Такой порядок
возможен, например, когда A успел прочитать создаваемый ADR, затем задержался на
другом файле, а B после удаления ADR завершился быстрее.

**Impact:** после серии внешних create/change/delete итоговый autocomplete,
diagnostics, Definition Provider и CodeLens могут отражать не последнее
состояние файлов. При перекрывающихся изменениях manifest позднее завершившийся
старый refresh также может вернуть старые source paths и перевесить watcher-ы
на них. Это нарушает основной внешний Harness-flow, для которого добавлен
watcher refresh.

**Fix direction:** Сделать refresh single-flight с dirty/coalescing semantics
либо ввести generation token и применять результат только если он относится к
последнему запрошенному поколению. Commit `manifest`/`index`, rewatch,
validation и CodeLens event должны быть одной latest-only операцией. Добавить
deterministic unit regression с двумя управляемыми Promise: B завершается перед
A, после чего финальное состояние остаётся B и устаревший A не публикует event.
Отдельно покрыть production `false` path ожидаемой ошибки чтения, а не только
rejected Promise.
