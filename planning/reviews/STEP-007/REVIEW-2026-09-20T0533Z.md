## Findings

### F-001 — High — Mark acceptance action не работает на каноническом формате STEP

**Location:** `src/editor/codeActions.ts:7-12`;
`planning/tasks/TEMPLATE.md:51-54`; `planning/tasks/STEP-007.md:57-63,128-130`;
`tests/unit/editor/providers.test.ts:24-33`.

**Scenario:** Given реальный STEP, созданный по canonical template, где критерий
записан как `- Проверяемый критерий`, when пользователь ставит курсор на этот
критерий и запрашивает Code Actions, then условие `^- \[ \] ` ложно и action
«Отметить acceptance criterion выполненным» отсутствует. Unit-тест использует
синтетический `- [ ] Критерий`, которого нет ни в template, ни в текущем
STEP-007, поэтому дефект скрыт.

**Impact:** Acceptance criterion «Quick actions корректно обновляют файл» не
выполнен для реальных Harness STEP; одна из четырёх заявленных quick actions
фактически недоступна пользователю.

**Fix direction:** Поддержать canonical plain bullet внутри секции
`Acceptance criteria` и минимально преобразовывать именно его в `- [x] ...`
(с сохранением текста/отступа); существующий unchecked-checkbox вариант можно
оставить дополнительным. Добавить Extension Host regression через
`vscode.executeCodeActionProvider` с применением edit к временной копии
реального template и проверкой, что соседние строки не изменились.

### F-002 — High — PLAN CodeLens открывает файл, но не целевой STEP/секцию

**Location:** `src/editor/codeLens.ts:12`; `src/editor/activation.ts:52-53,81-85`;
`docs/requirements/SPEC.md:92-98`; `planning/tasks/STEP-007.md:119-123`.

**Scenario:** Given открыт `STEP-007.md`, when пользователь нажимает CodeLens
«Открыть PLAN», then lens вызывает `harness.editor.openPlan` без STEP ID, а
команда вызывает `openFile(...)` без аргумента `id`. `openFile` выбирает offset
`0`, поэтому редактор показывает начало `PLAN.md`, а не строку `STEP-007`.

**Impact:** Явный acceptance REQ-003 «Code lens открывает целевой
REQ/ADR/секцию PLAN.md» и план «позиционируется на найденный идентификатор/строку»
не выполнены. На длинном roadmap пользователь всё ещё ищет STEP вручную.

**Fix direction:** Передавать ID текущего STEP в command arguments, находить
этот ID в manifest-resolved roadmap и reveal/select его range. Проверить
реальным выполнением CodeLens command в Extension Host, а не только наличием
lens object.

### F-003 — High — Editor index остаётся stale после внешних изменений артефактов

**Location:** `src/editor/activation.ts:25,35-45,47-53`; отсутствие
`FileSystemWatcher` для `sources.requirements`, `protocol.taskDirectory`,
resolver-owned `adrDirectory` и manifest.

**Scenario:** Given STEP Editor уже активирован, when внешний agent/CLI создаёт
новый `STEP-NNN.md` либо удаляет/переименовывает ADR без изменения открытого
TextDocument, then ни один зарегистрированный handler не перезагружает index.
Autocomplete продолжает предлагать удалённый ID или не знает новый ID;
diagnostics/hover/definition используют то же stale состояние. Повторный
`Ctrl+Space` на уже набранном prefix также не создаёт text-change event.

**Impact:** Гарантия REQ-003 «Autocomplete предлагает только реально
существующие ID» нарушается в основном Harness-flow, где пользователь запускает
agent CLI вне Extension Host. Broken-reference diagnostics и навигация также
могут оставаться неверными до случайного редактирования документа.

**Fix direction:** Инвалидировать общий index через debounce на create/change/delete
manifest-resolved requirements/STEP/ADR paths; при изменении manifest перечитать
его и безопасно перевесить watcher-ы. После refresh повторно валидировать
открытые STEP. Добавить Extension Host regressions для внешнего create/delete,
аналогичные уже существующим watcher-тестам Explorer.

### F-004 — High — Definition/CodeLens теряют реальные пути и угадывают имя файла

**Location:** `src/editor/activation.ts:59-62,72-78`;
`src/editor/definitionProvider.ts:36-49`;
`tests/integration/editor.test.js:49-73`.

**Scenario:** Индексатор принимает STEP-файлы по
`/^STEP-\d+.*\.md$/`, поэтому `STEP-022-description.md` попадает в index. При
Alt/Ctrl+Click Definition Provider, однако, строит путь `${id}.md` и пытается
открыть несуществующий `STEP-022.md`. Обратная несовместимость есть и для ADR:
индексатор принимает `ADR-001.md`, но lookup ищет только имя, начинающееся с
`ADR-001-`. Текущий integration-тест проверяет только удобные fixture names
`STEP-1.md` и `ADR-001-editor-fixture.md`.

**Impact:** Существующий ID отображается в autocomplete/hover, но переход по
нему не работает. Это ломает добавленный по ручному F5-запросу Definition
Provider и создаёт внутреннее расхождение с собственным glob/index contract.

**Fix direction:** Хранить canonical URI/path каждой распарсенной записи в
`StepEditorIndex` и возвращать этот путь из CodeLens/Definition Provider вместо
повторного угадывания layout/filename. Добавить suffix-name и exact ADR filename
integration cases.

### F-005 — Medium — Broken-reference diagnostic указывает на первое упоминание ID в документе

**Location:** `src/editor/validation.ts:35-44`;
`tests/unit/editor/validation.test.ts:92-112`.

**Scenario:** Given неизвестный `REQ-999` сначала упомянут в `Context`, а затем
указан как broken reference в `Requirements`, when validation строит diagnostic,
then `content.indexOf(id)` подчёркивает prose в `Context`, а не ссылку из
`Requirements`. То же относится к missing ADR/STEP. Поздний range-regression
проверяет только уже найденные, но невыполненные dependencies и не покрывает
missing-reference branch.

**Impact:** Пользователь видит diagnostic/hover не на ошибочной ссылке — тот же
класс дефекта, который уже проявился вручную для нескольких dependencies.
Требование implementation plan о точном range не выполнено полностью.

**Fix direction:** Искать occurrence внутри соответствующей labeled section
или строки `Depends on`, а не глобально по document. Добавить по regression case
для REQ, ADR и missing STEP с более ранним одноимённым prose-упоминанием и
проверять offset плюс полную длину ID.

### F-006 — Medium — Ошибка чтения одного индексируемого файла может сорвать activation/refresh

**Location:** `src/editor/activation.ts:38-41,65-69`.

**Scenario:** Given файл удалён либо становится временно нечитаемым между
`readdir` и `readFile`, when `Promise.all` отклоняется, then surrounding
`try/catch` его не перехватывает, потому что promise возвращается без `await`.
При initial `loadIndex` исключение выходит из `registerStepEditor`; при debounce
refresh `.then(...)` не имеет rejection handler.

**Impact:** Ожидаемая локальная деградация optional source превращается в
ошибку activation или unhandled rejection при обычной файловой гонке.

**Fix direction:** Await/catch aggregate read и деградировать per-file либо
перечитать index целиком безопасно; refresh обязан иметь обработанную failure
ветку и сохранять последний корректный index. Покрыть исчезновение файла между
listing/read контролируемым unit-тестом.
