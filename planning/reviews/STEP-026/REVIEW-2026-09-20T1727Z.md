## Findings

### F-001 — Low — Durable unit regression использует synthetic Markdown grammar вместо runtime grammar из Implementation plan

**Location:** `tests/unit/editor/grammar.test.ts:25`; `planning/tasks/STEP-026.md`
(`Implementation plan`, пункт 3)

**Scenario:** Given план обещает загрузить installed Markdown grammar из реального
VS Code test runtime, when встроенная grammar изменит имена code/list scopes или
структуру вложенных правил, then synthetic fixture продолжит выдавать текущие
scope names и тест останется зелёным, даже если фактическая VS Code tokenization
регрессирует. Extension Host test scopes не наблюдает.

**Impact:** Текущее production-поведение корректно и независимо доказано reviewer
probe, поэтому finding не блокирует acceptance. Но будущий drift встроенной
Markdown grammar может не быть пойман CI именно тем test seam, который заявлен в
плане.

**Fix direction:** либо загружать в отдельном regression проверенную grammar из
VS Code runtime, подготовленного integration setup, либо exact-pin официальный
Markdown grammar package/fixture с явным provenance; если synthetic seam выбран
осознанно, синхронизировать формулировку Implementation plan и добавить runtime
scope smoke-check там, где Extension Host предоставляет стабильную наблюдаемость.
