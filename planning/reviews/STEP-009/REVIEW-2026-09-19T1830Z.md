## Findings

### F-001 — Medium (security) — control characters обходят redaction manual handoff

**Location:** `src/commands/baseCommand.ts:41-45`,
`src/api/agentDispatcher.ts:26,50-53`, `src/api/executors.ts:136-140`,
`tests/unit/api/agentDispatcher.test.ts:27-39`.

`sanitizeExternalText()` сначала заменяет CR/LF/control bytes пробелом, затем
ищет credential-shaped значения. Ввод `to\rken=real-secret` превращается в
`to ken=real-secret`: ключ `token` разрушен до redaction, но само значение
остаётся и попадает в `[start]`, `[manual fallback]` и `params.message` для
notification. Unicode line separators (`U+2028`/`U+2029`) также не удаляются и
могут визуально разрывать запись Output Channel. Аналогично не распознаются
распространённые token formats вроде `xoxb-*`.

**Impact:** пользовательский secret может сохраниться в Output Channel и
notification, а затем попасть в screenshot, bug report или скопированный
diagnostic output. Spawn или выполнение кода этот обход не даёт, но он прямо
нарушает REQ-005 и Acceptance STEP-009 об отсутствии raw secret/control data.

**Fix direction:** предпочтительно не повторять free-text в diagnostic sinks:
показывать canonical command family и безопасный placeholder. Если точный текст
необходим, нормализовать Unicode `Cc`/`Cf`/`Zl`/`Zp` fail-closed и выполнять
redaction до и после нормализации; добавить regressions для split credential
key, common token formats, Unicode separators и bidi controls.

### F-002 — Medium (correctness) — пустой text input создаёт неканонический handoff

**Location:** `src/commands/activation.ts:105-112`,
`src/commands/baseCommand.ts:41-45`, `src/api/executors.ts:16-25`.

`showInputBox()` и программный `explicitArg` допускают пустую строку. Затем
`dispatchViaAgent()` проверяет `ctx.freeText` по truthiness и строит `STEP ADD`
либо `PROJECT QUICK FIX` без обязательного `: <input>`. Whitespace-only ввод
даёт столь же невалидную команду с пустым required input. `writeInvocationPolicy()`
не распознаёт её как write-command и manual handoff предлагает пользователю
команду, которую CTS отклонит.

**Impact:** user-facing manual handoff не является canonical command и не может
быть выполнен по инструкции. Одновременно mutation pre-validation применяется
к ошибочно классифицированному read-only значению, что нарушает контракт
REQ-005/STEP-009.

**Fix direction:** запретить пустой/whitespace-only text input до dispatch,
строить команду по explicit `undefined` check и валидировать итоговую command
тем же CTS contract до manual handoff. Добавить unit и Extension Host cases для
empty, whitespace-only и control-only input.

### F-003 — Medium (verification) — отсутствует обязательный Extension Host regression hostile free-text

**Location:** `planning/tasks/STEP-009.md:40-48`,
`tests/unit/api/agentDispatcher.test.ts:27-39`,
`tests/integration/commands.test.js:38-97`.

Required FIX handoff требует owning-layer unit **и Extension Host** regressions
с token-shaped input, CR/LF и ANSI/control bytes. Текущий unit вызывает
`HarnessAgentDispatcher` напрямую, содержит CR и ANSI, но не LF. Все три
Extension Host сценария запускают только `harness.plan`; они не проходят через
реальный text-command path `harness.addStep`/`harness.quickFix`, i18n и
`showWarningMessage`, поэтому raw value в конечном UI sink не проверяется.
Отдельного dispatcher/UI scenario для incomplete Mutation policy также нет.

**Impact:** заявленный evidence не доказывает acceptance на фактическом
Command Palette → Output/UI path и не ловит F-001/F-002.

**Fix direction:** добавить Extension Host scenario с explicit hostile text,
перехватом Output Channel/notification и fake executors. Проверить отсутствие
raw secret, CR/LF/ANSI/Unicode separators, отсутствие spawn и actionable
pre-validation при неполной Mutation policy.

### F-004 — Medium (traceability) — активный Implementation plan противоречит ADR-010 и текущему Scope

**Location:** `planning/tasks/STEP-009.md:32-38,107-204`.

Верхняя часть task уже определяет manual-only MVP и выносит automatic executor,
context bundle, retry, auto-reload и cancellation CLI за scope. Но
Implementation plan всё ещё имеет `Plan status: Ready` и предписывает именно
automatic Codex/Claude spawn, stdin context, structured result, retry,
auto-reload и SIGTERM. Context одновременно утверждает, что отдельный FIX ещё
только предстоит, хотя текущий FIX уже записан в Evidence.

**Impact:** STEP содержит два несовместимых активных контракта; следующий агент
может следовать `Ready` plan и вернуть security-опасный automatic lifecycle,
нарушив Accepted ADR-010.

**Fix direction:** пересогласовать Implementation plan и Context с ADR-010,
явно пометив automatic plan superseded/historical либо создав актуальную plan
revision для manual-handoff scope. Не удалять историческое evidence.
