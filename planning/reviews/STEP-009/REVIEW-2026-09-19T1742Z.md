## Findings

### F-001 — High (verification / acceptance) — отсутствует обязательный Extension Host full cycle

**Location:** `src/api/agentDispatcher.ts:22, 37-40, 60-61`,
`src/api/executors.ts:187-190`, `tests/integration/commands.test.js:38-97`.

Integration tests проверяют только отсутствие spawn для `PLAN STEP` и manual
fallback. Они не запускают controlled executor через реальный Command Palette
path и поэтому не доказывают обязательный full cycle из STEP Verification:
stdin context, JSON result, Output Channel, `nextCommand`, reload изменённого
чистого документа и сохранение active editor.

`CliExecutor` в production dispatcher не получает подтверждённую capability
OS-level read isolation, вследствие чего read-only invocation блокируется до
spawn; mutating invocation также блокируется ADR-008. Это корректная
fail-closed реакция на текущие ADR, но не является завершённой Terminal
Integration по REQ-005 и STEP-009.

**Impact:** Acceptance criteria о структурированном terminal output,
auto-reload без потери фокуса и передаче контекста агенту не доказаны. Unit
tests не заменяют этот evidence: они mock-ят builder, reloader и executor.

**Fix direction:** отдельный `STEP FIX STEP-009` должен либо добавить
безопасный, доказанно isolated automatic executor и Extension Host contract
test его полного lifecycle, либо формально сузить продуктовый контракт через
новый traceable planning/architecture decision. Нельзя отмечать STEP как
выполненный на основании manual fallback.

### F-002 — Medium (verification / reliability) — Ctrl+C, retry и runtime recovery не проверены в реальном command path

**Location:** `tests/integration/commands.test.js:38-56`,
`tests/unit/api/agentDispatcher.test.ts:29-74`,
`tests/unit/api/executors.test.ts:195-229`.

Extension Host test вызывает `harness.cancelAgent` только после уже
завершившегося manual fallback: активного child process и keybinding
`Ctrl+C` в нём нет. Retry, pre-validation failure, malformed result и runtime
recovery покрыты лишь unit tests с mock executor'ом.

**Impact:** требуемые три уровня обработки ошибок и отмена без порчи состояния
не имеют end-to-end evidence в VSCode. Однопоточный guard `active` также не
проверен двумя перекрывающимися invocations.

**Fix direction:** добавить Extension Host contract scenarios для активного
безопасного test executor: cancel через зарегистрированную команду/keybinding,
agent failure с одной user-confirmed retry, malformed/runtime failure без
падения host и second invocation без второго spawn. Проверить active editor
до/после reload и failure `applyEdit`/`save`.
