## Findings

### F-001 — Medium (security) — успешный result обходит единую redaction boundary

**Location:** `src/api/executors.ts:71-76`,
`src/api/agentDispatcher.ts:115-120`, `src/commands/baseCommand.ts:52-58`.

`structuredResult()` очищает только `summary`. Поля `changedFiles` и
`nextCommand` сохраняются как внешние строки, после чего dispatcher выводит их
в Output Channel без `sanitizeExternalText()`, а `nextCommand` дополнительно
попадает в user-visible notification. Кроме того, Codex `item.completed` с
terminal JSON сначала публикуется как progress, и `unavailable` message
передаётся в UI без общей sanitizer boundary.

**Scenario:** prompt-injected executor возвращает существующий безопасный
workspace path с именем `token=real-secret` либо синтаксически canonical
`GIT COMMIT: token=real-secret`. Path validation/локальная command regex
принимают значение, после чего secret остаётся в `[changed files]` или
`[next command]` и в toast. Текущий regression проверяет redaction только
отдельного helper для Bearer/JSON строки.

**Impact:** F-005 предыдущего review фактически не закрыт; credential может
сохраниться в Output Channel/UI, хотя Evidence и ADR-008 заявляют единую
границу для всех external strings.

**Fix direction:** нормализовать, ограничить и очищать каждый внешний field до
любого Output/UI sink; для path/command лучше отклонять secret-shaped значения,
а не изменять их после semantic validation. Добавить сквозной dispatcher test
для `changedFiles` и `nextCommand`, проверяющий отсутствие raw secret.

### F-002 — Medium (correctness) — локальная проверка `nextCommand` всё ещё расходится с CTS

**Location:** `src/api/executors.ts:38-69`.

Ручной `isCanonicalCommand()` не является эквивалентом
`.project/command-transitions.json`. Например, он принимает
`HARNESS UPDATE CHECK > APPLY TO v0.5.0`: первый segment не имеет target, но
второй вводит его. Канонический validator возвращает для той же строки
`TARGET_MISMATCH` (`chain target cannot be introduced after the first segment`).

**Scenario:** agent предлагает такой `nextCommand`. Terminal result считается
успешным и UI рекомендует structurally invalid chain, который следующий
обязательный preflight немедленно отклонит.

**Impact:** заявленное закрытие прежнего result-validation finding неполно;
пользователь получает заведомо неисполняемую следующую команду, а локальная
копия CTS продолжит дрейфовать при изменении command graph.

**Fix direction:** использовать единый deterministic CTS parser/validator либо
его общий library contract. Добавить differential regressions для target
introduction/change, cross-domain chain и valid aliases вместо проверки только
нескольких positive examples.

### F-003 — Medium (verification/security) — Git hardening не доказан через реальный `core.fsmonitor` exploit seam

**Location:** `src/git/gitHelper.ts:34-40`,
`tests/unit/git/gitHelper.test.ts:18-24`; F-001 предыдущего review.

Тест проверяет лишь возвращённый объект `safeGitEnvironment()`. Он не создаёт
репозиторий с executable `core.fsmonitor`, не вызывает фактический
`getGitSnapshot()` и не проверяет отсутствие marker после обоих Git процессов.
Также не захватывается argv, поэтому удаление `-c core.fsmonitor=false` из
production call site оставит текущий regression зелёным.

**Scenario:** будущий refactor сохраняет helper, но перестаёт передавать его env
или `-c` override в один из `branch/status` вызовов. Все текущие unit и
Extension Host tests проходят, repository-controlled fsmonitor снова
исполняется до manual fallback.

**Impact:** security boundary F-001/ADR-008 основана на неполном evidence;
регрессия вернёт pre-consent code execution без сигнала CI.

**Fix direction:** добавить temp-repository regression с локальным
`core.fsmonitor`, пишущим marker, вызвать реальный `getGitSnapshot()` и доказать
успех snapshot при отсутствии marker. Дополнительно захватить/проверить env и
argv обоих вызовов.

### F-004 — Medium (compatibility/security) — environment allowlist не покрывает документированные способы запуска CLI

**Location:** `src/api/executors.ts:13-16,110-115`,
`tests/unit/api/executors.test.ts:22-29`,
`tests/integration/commands.test.js:38-97`.

Статический allowlist Codex пропускает документированные `CODEX_HOME`,
`CODEX_ACCESS_TOKEN`, workload identity (`OPENAI_FEDERATION_RULE_ID`,
`OPENAI_IDENTITY_TOKEN_FILE`, `OPENAI_WORKLOAD_IDENTITY_CONTEXT`) и
`CODEX_CA_CERTIFICATE`. Он также не умеет передать пользовательское имя
provider credential из `config.toml → env_key`. Allowlist Claude пропускает
документированные gateway/provider/mTLS варианты, включая
`ANTHROPIC_AWS_API_KEY`, `ANTHROPIC_AWS_BASE_URL`,
`ANTHROPIC_BEDROCK_BASE_URL`, `ANTHROPIC_VERTEX_BASE_URL`,
`CLAUDE_CODE_USE_FOUNDRY`, `ANTHROPIC_CUSTOM_HEADERS`,
`CLAUDE_CODE_CERT_STORE`, `CLAUDE_CODE_CLIENT_CERT` и
`CLAUDE_CODE_CLIENT_KEY`; lower-case proxy variants также теряются.

Регрессия при этом проверяет только Codex с `OPENAI_API_KEY`, `HTTPS_PROXY`,
`HOME` и одним unrelated secret. Она не покрывает Claude, platform-home
boundary и явное исключение `GIT_CONFIG_*`. Extension Host no-spawn coverage
выполняет только `PLAN STEP` для Codex/Claude; остальные mutating command
families (`PROJECT INIT`, `STEP ADD`, `IMPLEMENT`, `REVIEW`, `FIX`, `RUN`,
`PROJECT QUICK FIX`, `PROJECT RECONCILE`) не проходят через matrix test.

**Scenario:** Codex работает из terminal через access token/workload identity
или custom provider `env_key`, а Claude — через AWS/Vertex/Foundry либо
enterprise gateway/mTLS. Extension удаляет нужную переменную, оба automatic
executor'а завершаются auth/network ошибкой, и единственный retry повторяет тот
же заведомо непригодный environment. Отдельно классификация одной canonical
write family может измениться на read path и дойти до executor; имеющиеся 242
unit и 18 Extension Host scenarios останутся зелёными.

**Impact:** F-004 предыдущего review и ADR-008 требуют allowlist, сверенный с
документированными auth/provider/proxy/certificate variables. Реализация ломает
штатные enterprise/automation конфигурации и не доказывает no-spawn для всей
write command surface.

**Fix direction:** сформировать versioned per-executor allowlist по официальным
[Codex environment variables](https://developers.openai.com/docs/config-file/environment-variables)
и [Claude environment variables](https://code.claude.com/docs/en/env-vars),
предусмотреть explicit trusted additions для Codex `env_key`; добавить
table-driven tests для auth/provider/proxy/certificate/platform-home, с
отрицательными unrelated и `GIT_CONFIG_*` cases. Отдельно покрыть policy/no-spawn
всех canonical mutating command families, включая Codex и Claude fallback.

### F-005 — Medium (security/observability) — sanitizer допускает log forging и распространённые secret formats

**Location:** `src/api/executors.ts:104-108,184-188`,
`src/api/agentDispatcher.ts:105-132`.

`sanitizeExternalText()` только обрезает строку и применяет два regex. Он не
удаляет CR/LF/ANSI/control characters, не распознаёт standalone credentials
(`ghp_...`, `sk-...`, access token без `name=`) и для quoted JSON secret со
space редактирует лишь часть до первого пробела. Codex terminal payload также
проходит через progress sink до структурной нормализации.

**Scenario:** executor выдаёт progress `ok\n[result] success`, ANSI sequence
или `{"token":"secret first second"}`/standalone access token. Output Channel
получает поддельную строку lifecycle либо незаредактированный хвост/credential;
текущий helper test с одним Bearer и компактным JSON остаётся зелёным.

**Impact:** Output Channel нельзя считать надёжным evidence, а credential может
остаться в UI/log несмотря на заявленный единый sanitizer.

**Fix direction:** ввести sink-specific normalization: удалить/экранировать
control characters и line breaks, не логировать terminal `item.completed` как
progress, ограничить безопасный progress schema и покрыть standalone/common
token patterns, quoted values с whitespace и ANSI/CRLF regression cases.
