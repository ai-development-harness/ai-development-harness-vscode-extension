## Findings

### F-001 — Medium (correctness/localization, verification) — invalid text input остаётся русским в English locale и не проверяется реальным E2E sink

**Location:** `src/commands/activation.ts:105-115`,
`tests/integration/commands.test.js:151-158`,
`planning/tasks/STEP-009.md:42-49,94-99`, ADR-011 Decision 5.

Command Palette отсекает empty, whitespace-only и control-only input до
dispatcher, но подставляет в локализованный template hardcoded русскую причину
`Введите непустое описание без управляющих символов.`. При выбранном English
locale пользователь получает смешанное сообщение: английский
`Cannot build safe agent context` и русскую причину. Dispatcher-owned direct
invocation уже использует `harness.agent.preValidation.invalidCommand`, но
обычный `harness.addStep` до него не доходит.

Extension Host scenario не обнаруживает регрессию: он перехватывает только
Output Channel и `showWarningMessage`, тогда как эта ветка вызывает
`showErrorMessage`. Тест проверяет лишь отсутствие старого marker-текста
`[manual fallback]`/`manualFallback`, не требует RU/EN actionable blocker и не
ставит fake Codex/Claude marker для invalid path. Поэтому заявленная в Required
FIX и Verification проверка localized invalid blocker/no-spawn не доказана.

**Impact:** REQ-006 и ADR-011 нарушаются в основном Command Palette path;
английский UI показывает русский текст. Обязательный invalid-input regression
может оставаться зелёным при полном исчезновении error notification или при
попытке запуска executor из этой ветки.

**Fix direction:** передавать в `harness.agent.preValidation` значение
`i18n.t('harness.agent.preValidation.invalidCommand')`, не hardcoded prose.
Расширить Extension Host harness: перехватывать `showErrorMessage`, выполнить
empty/control-only input в RU и EN, потребовать точный локализованный blocker и
отсутствие marker от fake Codex/Claude; сохранить проверку отсутствия handoff.
