## Findings

### F-001 — High (security) — Git запускается до consent с executable config из repository

**Location:** `src/git/gitHelper.ts:26-32`,
`src/api/contextBuilder.ts:62`, `src/api/agentDispatcher.ts:47-60`.

`buildAgentContext()` вызывает `git status` до write-consent. Trusted absolute
`/usr/bin/git` не делает сам repository доверенным: local Git config может
задать executable `core.fsmonitor`, который `status` запустит с правами
Extension Host.

**Scenario:** пользователь открывает подготовленный workspace с Git metadata,
где `core.fsmonitor` указывает на payload. Даже если пользователь затем
отклоняет workspace-wide write consent, payload уже выполнен во время сборки
контекста.

**Impact:** выполнение workspace-controlled кода до заявленной security
boundary; отдельный consent ADR-006 не защищает этот путь.

**Fix direction:** запускать Git с fail-closed config override как минимум для
`core.fsmonitor`, очищать влияющие `GIT_CONFIG_*`, выставлять
`GIT_OPTIONAL_LOCKS=0` и добавить regression с fsmonitor-marker, который не
должен появиться.

### F-002 — High (architecture/security) — write consent не раскрывает host-wide read

**Location:** `src/api/executors.ts:29-31,164`,
`src/api/agentDispatcher.ts:93-101`; ADR-006/ADR-007.

Codex `workspace-write` и Claude `acceptEdits` + `Read` ограничивают запись, но
не доказывают path-scoped чтение. Write flow передаёт `HOME`, запускает CLI в
исходном workspace и предупреждает пользователя только о workspace-wide
записи. Поэтому prompt injection из STEP/ADR может попросить агент прочитать
credentials или конфигурацию вне workspace и отправить их remote model.

**Scenario:** изменённый STEP просит прочитать `$HOME/.config/gh/hosts.yml`,
SSH/config credentials либо другой host-файл. Пользователь подтверждает запись
в workspace, не получая информации о более широкой read boundary.

**Impact:** возможное раскрытие host credentials за границей, которую UI и
architecture описывают как workspace-scoped. ADR-007 закрывает только
read-only invocation и не разрешает этот write-path gap.

**Fix direction:** принять явный architecture contract для write invocation:
OS-level containment с минимальным auth/config mount либо честный informed
consent/manual fallback. Изменение устойчивой boundary оформить ADR, а не
скрытой implementation detail.

### F-003 — High (security/correctness) — cancel не останавливает descendant в новой POSIX session

**Location:** `src/api/executors.ts:105-109`;
`tests/unit/api/executors.test.ts:162-176`;
`tests/integration/commands.test.js:66-87`.

POSIX cancel посылает signal только process group `-child.pid`. Обычный
background descendant из regression остаётся в этой group, но процесс может
вызвать `setsid` и покинуть её.

**Scenario:** executor или запущенная им команда создаёт
`setsid ... >/dev/null 2>&1 &`, затем пользователь нажимает Ctrl+C. Dispatcher
возвращает `cancelled`, а отделившийся процесс продолжает менять workspace.

**Impact:** нарушена acceptance-гарантия «Ctrl+C без порчи состояния файлов»;
текущий green regression даёт false positive только для одного PGID.

**Fix direction:** использовать OS containment/supervisor, который уничтожает
всё дерево независимо от PGID (например cgroup/Job Object либо эквивалент), и
добавить regression с detached `setsid` descendant и delayed marker.

### F-004 — High (correctness/compatibility) — production env удаляет штатные auth/network настройки CLI

**Location:** `src/api/executors.ts:162-164`.

Child получает только `PATH`, `HOME` и `LANG`. Это удаляет документированные
auth/provider/proxy/certificate variables, включая Codex API/access-token
variables и Claude `ANTHROPIC_API_KEY`, `HTTPS_PROXY`, custom CA, Bedrock,
Vertex и gateway configuration. Ручные smoke-тесты выполнялись не через этот
production env, а fake executors не проверяют его контракт.

**Scenario:** CLI работает из terminal с API-key, enterprise proxy/custom CA
или cloud-provider environment, но из extension завершается auth/network
ошибкой; один retry повторяет тот же заведомо сломанный env.

**Impact:** primary/secondary integration не работает в штатных automation и
enterprise конфигурациях, вопреки ADR-004 о переиспользовании настроенной CLI
authentication.

**Fix direction:** ввести per-executor allowlist документированных
auth/provider/proxy/certificate variables и platform home variables, не
наследуя environment целиком и не логируя значения. Fake executable должен
доказать передачу разрешённых имён и отсутствие unrelated secrets. Основание:
[Codex environment variables](https://learn.chatgpt.com/docs/config-file/environment-variables),
[Claude Code proxy/auth variables](https://docs.anthropic.com/en/docs/claude-code/corporate-proxy).

### F-005 — Medium (security) — external strings попадают в Output Channel/UI без единой sanitization

**Location:** `src/api/executors.ts:100,170,179-181`,
`src/api/agentDispatcher.ts:83-85,122-136`.

Текущий regex закрывает только небольшой набор `name=value`/`name:value`.
`Authorization: Bearer ...`, JSON credential fields, terminal summary и ряд
runtime/result paths проходят без общей sanitization; `item.completed` text
дополнительно логируется как progress до разбора terminal result.

**Scenario:** CLI или prompt-injected agent возвращает credential в progress,
structured error либо summary. Значение остаётся в Output Channel и/или
notification.

**Impact:** нарушено требование implementation plan не логировать secrets;
bounded output сам по себе не является redaction.

**Fix direction:** единая bounded sanitization на границе всех external
strings, запрет логировать terminal payload как progress и regressions для
Bearer/JSON/распространённых credential formats.

### F-006 — Medium (correctness/verification) — Windows cancel fail-open и не проверен real cancel seam

**Location:** `src/api/executors.ts:102-109`;
`tests/unit/api/executors.test.ts:189-192`.

При отсутствующем или некорректном `SystemRoot`
`windowsTaskkillExecutable()` возвращает `undefined`, но обе cancel-ветки
становятся no-op, а invocation продолжает ждать естественного завершения.
Единственный Windows test проверяет pure string helper: он не исполняет
Windows-ветку `terminateProcessTree`, не подставляет decoy `taskkill.exe` в
CWD/PATH и не доказывает завершение child/tree.

**Impact:** Ctrl+C может не остановить mutating agent; требование предыдущего
F-001 о Windows-focused regression формально и фактически не закрыто.

**Fix direction:** fail-closed activation/preflight либо надёжный Job
Object/direct-child fallback. Добавить injectable platform/runner seam или
Windows CI test, который доказывает абсолютный system executable, отсутствие
запуска decoy и фактическое завершение process tree.

### F-007 — Medium (scope/security) — текущий diff ослабляет repository runtime policy вне STEP-009

**Location:** `.codex/config.toml:23`; Mutation policy STEP-009.

Diff комментирует явный `sandbox_mode = "workspace-write"`. Файл не входит в
Allowed scope STEP-009, изменение не объяснено в plan/evidence и переводит
runtime posture на внешний/default profile, который repository больше не
контролирует.

**Impact:** unrelated security-sensitive mutation может попасть в commit
STEP-009 и сделать поведение root-agent зависимым от машины пользователя.

**Fix direction:** убрать изменение из diff STEP-009 либо оформить отдельное
traceable architecture/runtime изменение с собственным обоснованием и
verification.
