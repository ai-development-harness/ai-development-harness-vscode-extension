## Findings

### F-001 — High — длинный корректный JSONL обрезается до финального результата

**Location:** `src/api/executors.ts:10,104-115`;
`tests/unit/api/executors.test.ts:21-31`.

Один и тот же лимит 64 KiB применяется не только к diagnostic stderr, но и ко
всему stdout transport. `append()` сохраняет начало потока и отбрасывает хвост,
а Codex помещает итоговый `item.completed` и `turn.completed` именно в хвост
JSONL. Обычная длительная IMPLEMENT/FIX-команда с progress/tool events больше
64 KiB поэтому успешно изменит workspace, после чего normalizer увидит
усечённый поток и вернёт `malformed`. Extension не покажет реальный result, не
перезагрузит изменённые документы и не предложит следующую команду.

**Исправление:** разбирать Codex JSONL потоково и bounded-хранить только
необходимые terminal/error/result events; для Claude ввести явный `too-large`
result вместо тихого усечения. Добавить regression с progress >64 KiB и
валидным финальным result.

### F-002 — High — неполный result ошибочно считается успешным

**Location:** `src/api/executors.ts:32-37`;
`src/api/contextBuilder.ts:70`; `src/api/agentDispatcher.ts:72-77,108-114`.

Prompt объявляет schema с `summary`, `changedFiles` и `nextCommand`, но
`structuredResult()` требует только `summary`; два поля, от которых зависят
auto-reload и предложение следующей команды, optional. Ответ
`{"summary":"готово"}` проходит как success, хотя extension не знает, какие
файлы агент изменил, и не показывает next command. Это тихо нарушает две
acceptance criteria REQ-005 после уже выполненной mutation.

**Исправление:** валидировать все обязательные поля единой schema (включая
workspace-relative `changedFiles` и допустимую canonical `nextCommand`, либо
явный terminal `null` по документированному контракту) и добавить negative
tests для каждого отсутствующего/невалидного поля.

### F-003 — High — Git snapshot блокирует все agent-команды на Windows

**Location:** `src/git/gitHelper.ts:23-29`; `src/api/contextBuilder.ts:57-58`;
`package.json:12-15`; `tests/unit/git/gitHelper.test.ts:3-14`.

При отсутствии undocumented `HARNESS_GIT_EXECUTABLE` helper всегда запускает
`/usr/bin/git`. Пакет не ограничен Linux, но на Windows такого пути нет:
context builder вернёт pre-validation error до выбора Codex/Claude, поэтому ни
одна из девяти делегируемых MVP-команд не стартует. Тест использует реальный
Unix checkout и не выявляет дефект.

**Исправление:** определить cross-platform trusted Git strategy (явная
настройка/VSCode Git API или другой provenance-aware resolver), отразить её в
configuration/architecture и покрыть platform-independent mock tests. Нельзя
возвращаться к неограниченному поиску по writable `PATH`.

### F-004 — High (security) — workspace может подменить trusted executable

**Location:** `package.json:22-35`;
`src/api/agentDispatcher.ts:15-18`; `src/api/executors.ts:56-63,101`.

Путь executor читается обычным `getConfiguration().get()`, поэтому
репозиторий может задать его через tracked `.vscode/settings.json`. Например,
workspace-setting `harness.executables.codex=/bin/bash` вместе с файлом
`exec` приводит к запуску `/bin/bash exec --json ...` после consent. Диалог
показывает canonical command и Mutation policy, но не identity/resolved path
процесса; пользователь подтверждает agent write, фактически запуская
подконтрольный репозиторию код с правами Extension Host.

**Исправление:** разрешать executable только из Global/Machine configuration,
через `inspect()` fail-closed отклонять workspace/folder override и показывать
resolved realpath executor в consent. Добавить regression с workspace-setting
на `/bin/bash` и репозиторным `exec`.

### F-005 — Medium (security) — временный bundle не создаёт заявленный read boundary

**Location:** `src/api/executors.ts:83-101`;
`src/api/contextBuilder.ts:61-72`; `docs/architecture.md:37`.

Для read-only invocation меняются только `cwd` и `-C`; OS-доступ процесса к
исходному workspace и home не ограничен. Более того, prompt явно раскрывает
абсолютный `Workspace: ...`, поэтому инструкция из выбранного STEP/ADR может
попросить Codex/Claude прочитать `.env` или другой файл по абсолютному пути.
`codex -s read-only` запрещает запись, а Claude `Read` разрешает чтение; ни один
режим не является copy-only filesystem sandbox. Комментарий в коде и
architecture claim о передаче только allowlisted context поэтому ложны.

**Исправление:** использовать реальную path-scoped read isolation либо не
передавать исходный путь и запускать executor в изолированном окружении,
доступном только bundle. Если это невозможно, нужен честный informed consent и
ADR reconciliation; test должен содержать decoy secret вне allowlist.

### F-006 — Medium — cancellation не доказывает остановку команды во всех поддерживаемых состояниях

**Location:** `src/api/executors.ts:66-69,111-113`;
`src/api/agentDispatcher.ts:24-27,56-70`;
`tests/unit/api/executors.test.ts:73-89`;
`tests/integration/commands.test.js:66-85`.

На Windows `child.kill()` завершает только прямой процесс, а не дерево CLI.
Кроме того, Ctrl+C во время consent/retry лишь abort'ит signal, но ожидаемый
`showWarningMessage()` не закрывается, поэтому invocation остаётся `active` до
ручного ответа. Тесты проверяют только завершение Promise для Unix shell и не
наблюдают grandchild, retry/consent, `dispose()` или состояние файлов.

**Исправление:** реализовать и проверить platform-specific tree termination;
сделать UI waits cancellation-aware и добавить сценарии surviving grandchild,
cancel в consent/retry, dispose и отсутствие partial result/file corruption.

### F-007 — Medium — full-cycle evidence не проверяет заявленный пользовательский результат

**Location:** `tests/integration/commands.test.js:87-142`;
`tests/unit/api/agentDispatcher.test.ts:25-43`;
`tests/unit/api/contextBuilder.test.ts:28-41`.

Extension Host success проверяет prompt, reload и active editor, но не
наблюдает Output Channel, summary/changed-files output, next-command UI или
progress. Fallback-сценарий доказывает только `Codex unavailable → Claude
success`, а не обязательный two-executor-unavailable/manual fallback. Также
нет regressions для длинного JSONL, полного состава protocol/manifest/exact
REQ/git context, retry exhaustion и pre-validation без spawn. Поэтому Evidence
утверждает больше, чем реально доказано тестами.

**Исправление:** добавить наблюдаемые contract assertions на Output Channel и
notifications/actions, обе unavailable ветки, полный context и перечисленные
failure/cancellation cases; не считать raw CLI smoke заменой Extension Host
пути после изменения argv/environment.
