## Findings

### F-001 — High (security/contract) — free text from a later CTS segment reaches both handoff sinks

**Location:** `src/api/commandPolicy.ts:76-82,125-133`;
`src/api/agentDispatcher.ts:54-62`; ADR-011 Decision 2–3.

`canonicalCommandMetadata()` returns only the first segment metadata but stores
the whole raw root command. The deterministic CTS validator accepts:

```text
GIT CHECK > COMMIT: ordinary-intent-sentinel > PUSH > PR
```

For that chain the extension records `GIT CHECK` as `input=none`; consequently
`manualHandoffLabel()` returns the full chain as an exact label. The original
text from `GIT COMMIT` reaches Output Channel, `manualFallback.params.message`
and the notification. This violates ADR-011 never-echo boundary for an
optional input with supplied text.

**Remediation:** retain normalized metadata for every segment, aggregate a
`containsFreeText` signal and use a non-executable localized descriptor whenever
any segment contains required or supplied optional input. Add an owning test for
both UI sinks of this exact chain.

### F-002 — High (security/correctness) — chain effect policy is fail-open and extension parser accepts an invalid initial alias

**Location:** `src/api/commandPolicy.ts:92-98,126,141-156`;
`.project/command-transitions.json:188-219,222-301`.

Policy takes the effect only from the first segment. Thus valid CTS chains
`GIT CHECK > PUSH > PR`, `HARNESS UPDATE CHECK > APPLY` and the F-001 chain
are reported read-only even though they contain remote or filesystem mutation.
This is a direct repeat of F-002 fail-open classification at chain scope.

The parser also accepts `HARNESS APPLY` as a first segment by applying
`continuationAliases` without an index guard, while the deterministic validator
returns `UNKNOWN_OPERATION`; the alias is valid only after `HARNESS UPDATE
CHECK` in a chain.

**Remediation:** validate and classify every normalized segment, fail closed if
any segment lacks an effect contract, aggregate the strongest effect, and allow
continuation aliases only at a permitted non-initial segment. Add regressions
for all cited chains and the rejected standalone alias.

### F-003 — Medium (security/contract) — exact no-text label preserves outer control bytes

**Location:** `src/api/commandPolicy.ts:76-77,126`;
`src/api/agentDispatcher.ts:59-62`; ADR-011 Decision 5; STEP-009 Acceptance.

Parsing normalizes with `value.trim()`, but `metadata.command` retains the raw
input. The authoritative validator accepts a CR/LF-wrapped `GIT PUSH` and
normalizes it to `GIT PUSH`; the extension returns the raw wrapped string to
both UI sinks. The same applies to tab and Unicode U+2028/U+2029 wrappers.

**Remediation:** construct exact labels exclusively from normalized CTS tokens,
or reject outer control/format bytes before handoff. Cover Output Channel and
notification for wrapped no-input commands.

### F-004 — Medium (scope/traceability) — residual automatic-lifecycle code and stale canonical metadata remain

**Location:** `src/api/workspacePaths.ts:9-57`;
`src/commands/agentDispatcher.ts:1-24`; `planning/tasks/STEP-009.md:667-675`;
`docs/requirements/STATUS.md:11`; `docs/requirements/SPEC.md:13-21`.

`CliExecutor`, context builder, reloader and Git snapshot are removed, and the
public executor/cancellation surfaces are correctly absent. However:

- unused production `workspacePaths.ts` still describes agent prompt/result and
  changed-file/reload paths, and is used only by its own tests;
- unused `NotImplementedAgentDispatcher` still documents future automatic
  Codex/Claude integration and sends raw `ctx.protocolName` in params;
- canonical STEP Review status still says latest verdict PASS at report 2038
  despite the latest immutable review 2108 being FAIL;
- `docs/requirements/STATUS.md` uses `В работе`, which is not an allowed REQ
  lifecycle value (`SPEC.md` permits `Запланировано`, `Частично`, `Выполнено`,
  `Отложено`, `Отменено`).

**Impact:** a manual-only MVP keeps dormant automatic support and its canonical
status projections conflict with immutable evidence.

**Remediation:** remove the unused automatic-only modules/tests or move them to
an explicitly separate future scope; correct task review metadata and use the
valid REQ status `Частично` until a PASS review is recorded.

### F-005 — Medium (verification) — required fake-executor no-spawn regression was removed instead of replaced

**Location:** `tests/integration/commands.test.js:63-180`;
`planning/tasks/STEP-009.md:42-49,96-99`.

The current integration suite verifies reachable UI sinks but removed the fake
Codex/Claude executables and marker assertions. Source-level absence supports
the current no-spawn claim, but the task explicitly requires an Extension Host
regression proving fake executables do not run for valid and invalid paths.

**Remediation:** restore a minimal Extension Host no-spawn regression without
reintroducing production executable configuration: expose fake executables via
test-only PATH and assert no marker is created for valid and invalid manual
handoff paths.
