## Findings

### F-001 — Medium (security/contract) — release target обходит нормализацию exact handoff

**Location:** `src/api/commandPolicy.ts:114-135`;
`src/api/agentDispatcher.ts:29-46`; `tests/unit/api/commandPolicy.test.ts:6-60`;
ADR-011 Decision 2/5; STEP-009 Acceptance.

`release-optional` target разбирается через `^TO\s+(\S+)$`. `\S+` принимает
ESC, NUL и bidi format characters; затем raw target добавляется в
`metadata.command`. Поскольку target не считается free text,
`manualHandoffLabel()` передаёт его как exact label в Output Channel и
`manualFallback.params.message`, а Command layer — в notification.

Например, authoritative CTS и TypeScript policy принимают
`HARNESS UPDATE CHECK TO v1<ESC>[31m` и `... TO v1<U+202E>`. Это нарушает
acceptance о недопустимости ANSI/control bytes в обоих sink. Даже benign
`HARNESS UPDATE CHECK TO v1.2.3` реконструируется как
`HARNESS UPDATE CHECK v1.2.3`: literal `TO` теряется, поэтому label уже не
является exact canonical command. Для chain ошибка повторяется в каждом
segment.

**Impact:** handoff допускает control-sequence/UI-spoofing через target и
показывает пользователю неканоническую команду для обычного release tag.

**Fix direction:** валидировать release target по явной safe grammar либо как
минимум отклонять `Cc`/`Cf`/`Zl`/`Zp` и ANSI bytes; строить normalized segment
по target kind с обязательным `TO`. Добавить owning tests для benign и hostile
standalone/chain target, проверяющие оба sink.

### F-002 — Medium (architecture/security documentation) — architecture заявляет отсутствующую path-containment boundary

**Location:** `docs/architecture.md:39`; `src/parser/yamlParser.ts:66-101`;
`src/explorer/vscodeReader.ts:23-34`; `src/explorer/actions.ts:73-127`;
deleted `src/api/workspacePaths.ts`.

Обновлённый architecture baseline утверждает, что перед чтением всех
artifact-файлов выполняются lexical containment и `realpath`-проверка и что
traversal/symlink наружу отклоняются. Фактический Parser принимает path fields
как произвольные строки, а Explorer/Actions передают `path.join(workspaceRoot,
manifestPath)` в filesystem API без lexical или `realpath` guard. Удалённый
`workspacePaths.ts` был единственным найденным модулем с такими проверками и
относился к superseded agent context/reload path; replacement для artifact
read/write path отсутствует.

Конкретный manifest path `../../outside.md` резолвится `path.join` за пределы
workspace, а symlink target также не проверяется. Следовательно, расширение
может читать artifact вне workspace, хотя canonical architecture заявляет
противоположную security boundary.

**Impact:** документация и фактическая boundary расходятся; review не может
подтвердить синхронизацию architecture deliverable, а downstream STEP может
ошибочно полагаться на несуществующий guard.

**Fix direction:** не приписывать удалённому automatic-lifecycle guard общую
artifact safety. Исправить baseline на фактическое состояние и вынести общую
containment-защиту Parser/filesystem boundary в отдельный corrective STEP,
если invariant должен быть реализован; не добавлять unrelated production fix
в STEP-009.

### F-003 — Medium (verification) — новый CTS chain parser не имеет negative regression для структурных ошибок

**Location:** `tests/unit/api/commandPolicy.test.ts:31-48`;
`tests/unit/api/agentDispatcher.test.ts:69-96`; STEP-009 Acceptance/Verification.

Тесты проверяют unknown operation и standalone continuation alias, но не
проверяют основные отрицательные ветки нового multi-segment parser:
отсутствующий edge (`GIT PUSH > CHECK`), смену domain (`GIT CHECK > STEP REVIEW
STEP-009`) и смену target (`STEP PLAN STEP-009 > REVIEW STEP-010`). Нет и
dispatcher assertion, что такие команды дают localized blocker без Output
handoff/UI warning.

Текущая ручная inspection показала, что эти три примера отклоняются, но это не
заменяет regression: TypeScript повторно реализует authoritative CTS parser,
а исправляемый дефект как раз находился в chain-level semantics.

**Impact:** обязательная pre-validation invalid-chain boundary не защищена
тестом от расхождения с CTS и повторной утечки handoff при следующем изменении.

**Fix direction:** добавить table-driven owning tests для invalid edge,
cross-domain и target mismatch; на dispatcher level доказать localized
pre-validation result, отсутствие manual fallback в обоих sink и no-spawn.
