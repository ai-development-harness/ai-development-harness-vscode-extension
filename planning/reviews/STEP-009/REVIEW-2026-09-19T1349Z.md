## Findings

### F-001 — High (security) — context builder позволяет отправить внешний файл агенту

**Location:** `src/api/contextBuilder.ts:27-48`; входной контракт:
`src/parser/yamlParser.ts:79-112`.

Пути из manifest и связанных STEP соединяются с `workspaceRoot` через
`path.join()`, затем без containment-check и `realpath()` передаются в
`readdir()`/`readFile()`. Parser принимает произвольные строковые значения.

**Scenario:** вредоносный repository указывает в `protocol.file` путь с `../`
либо размещает symlink в разрешённой директории. После запуска команды файл за
пределами workspace попадает в prompt Codex/Claude.

**Impact:** утечка локальных секретов во внешний сервис; это нарушает
заявленный allowlisted boundary ADR-005 и security rationale STEP-009.

**Fix direction:** создать единый resolver для agent context: запретить
absolute/parent traversal, проверить `realpath` файла и родительского
каталога относительно realpath workspace, явно запретить либо безопасно
обработать symlink. Добавить regression cases для traversal, absolute path и
symlink.

### F-002 — High (security) — write permissions не ограничены Mutation policy

**Location:** `src/api/executors.ts:7-15`; связанный контракт:
`planning/tasks/STEP-009.md` → Mutation policy и ADR-004 Decision 7.

`isMutatingCommand()` определяет write-доступ только по префиксу имени
команды. Executor не получает и не применяет `targetStep.mutationPolicy`, а
Codex получает `workspace-write`, Claude — `acceptEdits` и `Read,Edit,Write`
для всего workspace.

**Scenario:** инструкция в artifact/prompt заставляет агента изменить файл за
пределами Allowed или прямо Forbidden path; CLI уже выдан неограниченный по
workspace write-доступ.

**Impact:** prompt injection может привести к изменению repository вне Scope,
несмотря на зафиксированную в STEP mutation policy.

**Fix direction:** fail-closed policy object из canonical command и parsed
Mutation policy; применять только реально enforceable executor scopes. Если
CLI не может ограничить пути, не выдавать automatic write без явного
подтверждения пользователя. Покрыть forbidden/out-of-scope mutation тестами.

### F-003 — High (correctness) — `RUN STEP` запускается в read-only sandbox

**Location:** `src/api/executors.ts:7-14`; `src/commands/run.ts:5-11`.

`RUN STEP-NNN` не входит в regex mutating-команд, поэтому получает Codex
`read-only` и Claude `plan`. При этом протокол определяет `STEP RUN` как
оркестрацию, которая может продолжить IMPLEMENT/FIX и выполнить mutation.

**Impact:** одна из зарегистрированных MVP-команд не может выполнить
предписанную runtime-семантику, а не просто теряет optional UX.

**Fix direction:** выводить permissions из фактического canonical child action
и разрешённой policy target STEP, а не из string-prefix.

### F-004 — High (correctness) — результат не содержит changed files и next command

**Location:** `src/api/types.ts:16-17`, `src/api/executors.ts:17-31`,
`src/api/agentDispatcher.ts:48-74`, `src/api/documentReloader.ts:21-44`.

Типы декларируют `changedFiles` и `nextCommand`, но normalizers их не извлекают,
dispatcher их не передаёт, а reloader обходит все чистые открытые документы.
Промпт также не задаёт агенту структурированную schema для этих полей.

**Impact:** не выполнены REQ-005: reload именно изменённых файлов и предложение
следующей команды. Ненужная перезагрузка всех открытых документов увеличивает
риск конфликтов и не является требуемым contract.

**Fix direction:** определить и запросить machine-readable result schema,
нормализовать поля в обоих adapters, показать next command и передать в
reloader только validated workspace-contained changed paths.

### F-005 — High (verification) — обязательный full-cycle integration test отсутствует

**Location:** `tests/integration/commands.test.js:19-36`;
Verification в `planning/tasks/STEP-009.md`.

Extension Host прогон проверяет регистрацию команд и read-only `STATUS PROJECT`.
Он не вызывает agent command с fake executable и не проверяет stdin/context,
Output Channel/result, reload, unavailable executor или cancel.

**Impact:** `npm run test:integration` зелёный, но не доказывает обязательный
полный цикл STEP-009.

**Fix direction:** добавить fixture с fake Codex/Claude executable и
Extension Host сценарии success, unavailable/error, cancel и reload без
изменения active editor.

### F-006 — High (verification) — transport и cancel unit-тестами не доказаны

**Location:** `tests/unit/api/executors.test.ts:3-15`,
`tests/unit/api/agentDispatcher.test.ts:36-43`; реализация:
`src/api/executors.ts:36-72`.

Тесты покрывают лишь args/prefix helper и готовый mocked `{ cancelled: true }`.
Нет проверки spawn с `shell: false`, stdin, normalizers, malformed/non-zero
output, Codex-to-Claude fallback, SIGTERM/close или wiring cancel command.

**Impact:** критические ветви external transport и отсутствие partial result
после cancel остаются непроверенными.

**Fix direction:** мокировать spawn на уровне `CliExecutor`; покрыть stdin,
оба JSON формата, failure/fallback и cancel lifecycle до/после spawn.

### F-007 — Medium (security/reliability) — cancel не является устойчивой границей

**Location:** `src/api/agentDispatcher.ts:18-20,23-60,84-86`;
`src/api/executors.ts:36-40`.

Cancel до spawn или во время retry dialog — no-op; child не завершает process
tree и не имеет bounded escalation; `dispose()` не отменяет invocation.

**Impact:** после ожидаемой пользователем отмены mutation может продолжиться
в дочернем/осиротевшем процессе.

**Fix direction:** invocation-scoped AbortController с проверкой после каждого
await, cancellation в dispose, завершение process group/tree с bounded grace
period и regression tests для cancel-before-spawn/retry/ignored SIGTERM.

### F-008 — Medium (security) — bare executable допускает подмену

**Location:** `src/api/executors.ts:47`; `src/git/gitHelper.ts:25-26`.

`codex`, `claude` и `git` запускаются bare names из PATH при cwd внутри
открытого repository.

**Impact:** на платформе/окружении с search order, допускающим workspace или
`.` в PATH, вредоносный repository может выполнить подменённый executable от
имени пользователя.

**Fix direction:** использовать configured/trusted absolute executable outside
workspace либо VS Code Git API и отклонять resolved executable внутри workspace.
