## Findings

### F-001 — High (security) — automatic read-only invocation нарушает ADR-007

**Location:** `src/api/executors.ts:91-103`; контракт:
`docs/adr/ADR-007-agent-read-boundary.md`, Decision 3.

`CliExecutor.invoke()` для любой non-mutating command создаёт temporary bundle
и затем автоматически запускает как Codex, так и Claude. Однако ADR-007
разрешает automatic read-only invocation только executor'у с подтверждённой
OS-level read isolation; bundle прямо не является такой изоляцией. Claude
`plan`/`Read` не имеет проверенного path-scoped read boundary, а код не
отличает его от Codex и не переводит invocation в manual fallback.

**Scenario:** пользователь запускает будущую read-only agent-команду при
настроенном Claude. Artifact из bundle инструктирует CLI прочитать другой
файл, доступный процессу, и extension автоматически передаёт управление CLI
без предусмотренного ADR-007 fallback.

**Impact:** нарушен принятый security contract; data-minimization ошибочно
становится автоматическим разрешением внешнему process.

**Fix direction:** ввести явную capability executor'а: automatic read-only
разрешать только при документально подтверждённой OS-level isolation, а для
остальных возвращать typed manual fallback до spawn. Удалить противоречащий
комментарий о том, что `cwd` bundle сам предотвращает чтение соседних файлов;
добавить regression для Claude read-only path.

### F-002 — Medium (correctness) — Output Channel не отображает progress агента

**Location:** `src/api/agentDispatcher.ts:40-115`; `src/api/executors.ts:112-128`;
REQ-005.

Executor потоково разбирает Codex JSONL, но сохраняет только terminal text,
completion и error. Progress/tool events отбрасываются; в `Harness` Output
пишутся лишь статические `[start]`, `[context]`, `[executor]`, `[result]` и
reload. Claude output также публикуется только после close.

**Scenario:** долгий IMPLEMENT/FIX выполняет tool calls несколько минут. До
окончания пользователю не виден фактический progress агента, хотя процесс
живёт и Output Channel открыт.

**Impact:** REQ-005 требует отображать progress и result; зелёный happy-path
test проверяет terminal result/reload, но не наблюдает progress.

**Fix direction:** добавить ограниченный/redacted progress callback из обоих
executor adapters в dispatcher и Output Channel; не логировать prompt или
неограниченный stderr. Добавить contract test, который наблюдает хотя бы одно
progress-сообщение до final result.
