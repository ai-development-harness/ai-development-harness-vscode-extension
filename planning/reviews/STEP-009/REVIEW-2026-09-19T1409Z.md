## Findings

### F-001 — High — PLAN и REVIEW ошибочно получают read-only permissions

**Location:** `src/api/executors.ts:9-16,106-119`; `src/commands/plan.ts:3-9`;
`src/commands/review.ts:3-9`; `tests/unit/api/executors.test.ts:15-19`.

`requiresWriteAccess()` не включает `PLAN` и `REVIEW`. Поэтому Codex получает
`read-only`, Claude — `plan`, а явный consent по ADR-006 не показывается, хотя
обе команды создают durable artifacts: Implementation plan и immutable review
report. Две MVP-команды не смогут выполнить предписанную runtime-семантику.

**Исправление:** заменить regex на семантическую policy классификацию команд,
включающую все mutation-команды, и покрыть фактические argv и consent для
каждой из них.

### F-002 — High — доверенным признаётся произвольный executable вне workspace

**Location:** `src/api/executors.ts:61-78,118,147`; `src/git/gitHelper.ts:23-29`;
`src/api/contextBuilder.ts:55-56`; `tests/unit/api/executors.test.ts:34-48`.

`resolveTrustedExecutable()` принимает любой executable из наследуемого `PATH`,
если его realpath расположен вне workspace. Это не устанавливает trusted
provenance: writable ранний каталог `PATH` позволяет подменить `git` либо CLI.
`git` запускается до consent, а CLI наследует environment и получает полный
prompt через stdin, поэтому результатом может стать RCE и раскрытие контекста.

**Исправление:** требовать configured/trusted absolute executable или
доверенный owner/location, санитизировать environment; не выполнять
подменяемый binary до consent. Добавить отрицательные tests для writable
`PATH` entry.

### F-003 — High — verification не доказывает обязательный полный цикл

**Location:** `tests/integration/commands.test.js:38-57`; Verification в
`planning/tasks/STEP-009.md`.

Единственный новый Extension Host scenario проверяет две строки stdin. Он не
проверяет Output Channel/result, список changed files, next command, внешнее
изменение и reload без смены focus, недоступный executor/agent error либо
cancel. Отдельно нет regression-test, что mutation/RUN показывает paths из
policy, отказ не запускает executor, а consent даёт нужный режим.

**Исправление:** добавить full-cycle tests с fake executor для success,
unavailable/error, reload/focus, cancellation и ADR-006 consent.

### F-004 — Medium — в prompt передаются нерелевантные REQ

**Location:** `src/api/contextBuilder.ts:14-17,57-70`.

`relevantSections()` разделяет документ только по heading уровня `#`/`##`,
тогда как REQ в `SPEC.md` имеют `###`. Для STEP-009 это отправляет весь раздел
`Требования`, а не только REQ-005. Это нарушает договорённость о релевантном
контексте и расширяет объём данных, передаваемых внешнему CLI.

**Исправление:** извлекать точные границы `### REQ-NNN` через parser либо
строгий section parser; добавить fixture минимум с двумя REQ и отрицательной
проверкой второго.

### F-005 — Medium — безопасная диагностика не защищает stderr агента

**Location:** `src/api/executors.ts:37,130,140`; `src/api/agentDispatcher.ts:49,65,102`.

Полный stderr/error text без truncation или redaction отображается в Output
Channel и UI. CLI либо агент может вернуть повторённый prompt или token, что
нарушает заявленную в STEP безопасную диагностику.

**Исправление:** применять ограничение длины и redaction перед Output/UI,
сохраняя диагностический тип; покрыть секретоподобные строки test case.

### F-006 — Medium — cancellation не гарантирует остановку process tree

**Location:** `src/api/executors.ts:81-96,131-140`; `src/api/agentDispatcher.ts:44-56`.

На Windows `child.kill()` завершает только прямой process. На POSIX escalation
таймер очищается по `close` лидера, поэтому helper, игнорирующий `SIGTERM`,
может продолжить работу после результата `cancelled`. При отмене во время
retry-dialog dispatcher после закрытия диалога возвращает исходную ошибку, а не
`cancelled`.

**Исправление:** обеспечить platform-specific tree termination с проверяемой
bounded escalation, не снимать escalation до подтверждения остановки tree;
сделать retry-dialog abort-aware и добавить соответствующие tests.

### F-007 — Medium — consent может быть привязан к неполной policy

**Location:** `src/parser/markdownParser.ts:322-339`; `src/commands/stepPicker.ts:30-34`;
`src/commands/activation.ts:97-125`; `src/api/agentDispatcher.ts:74-82`.

Malformed/missing Mutation policy превращается в пустые arrays с warnings,
которые теряются при выборе STEP. Confirmation показывает `-` и generic
`protocolName`, а не полный canonical command с target STEP, но всё же может
выдать workspace-wide write. Это не соответствует fail-closed policy ADR-006.

**Исправление:** перед write invocation fail-closed отклонять неполную policy
и показывать canonical command с выбранным STEP и parsed Allowed paths.

### F-008 — Medium — отсутствует explicit manual fallback при двух unavailable CLI

**Location:** `src/api/agentDispatcher.ts:85-103`; ADR-004 Decision 4.

После двух unavailable executors пользователь получает generic failure, но не
понятный offline/manual fallback/action, обязательный ADR-004.

**Исправление:** вернуть отдельный typed result для two-executor unavailable,
локализованное manual-mode сообщение/action и contract test.

### F-009 — Medium — changed files не отображаются пользователю

**Location:** `src/api/agentDispatcher.ts:57-62,93-97`;
`src/commands/baseCommand.ts:47-54`.

Validated `changedFiles` применяются только для reload, а Output содержит лишь
счётчики. Пользователь не видит, какие файлы сообщил агент, что не выполняет
пользовательский контракт результата.

**Исправление:** вывести validated workspace-relative paths в `Harness` Output
и добавить assertion в full-cycle test.
