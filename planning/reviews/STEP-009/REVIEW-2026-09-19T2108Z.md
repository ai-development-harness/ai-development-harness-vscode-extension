## Findings

### F-001 — High (security/contract) — ADR-011 реализован только для двух text-command family

**Location:** `src/api/agentDispatcher.ts:39-44,61-63,77-92`;
`src/commands/baseCommand.ts:53-59`; `.project/command-transitions.json:139-155,233-237`;
`docs/adr/ADR-011-safe-free-text-manual-handoff.md:26-44`.

`manualHandoffLabel()` распознаёт только `STEP ADD` и `PROJECT QUICK FIX`.
Однако CTS задаёт required input также для `SKILL FIND`, `SKILL INSTALL` и
`SKILL CREATE`, а optional input — для `GIT COMMIT`.

`SKILL FIND: ordinary-intent-sentinel`, `SKILL INSTALL: ordinary-intent-sentinel`,
`SKILL CREATE: ordinary-intent-sentinel` и
`GIT COMMIT: ordinary-intent-sentinel` проходят CTS validation. Для них функция
возвращает `sanitizeExternalText(command)`: нейтральный original intent не
secret-shaped и остаётся в label. Он попадает в Output Channel через
`appendLine(label)`, затем в `manualFallback.params.message` и notification как
i18n parameter. Это прямо нарушает ADR-011 Decision 3: raw free text не должен
попадать ни в одну handoff surface. `GIT COMMIT` без текста корректен: для
optional input без фактически переданного free text exact command разрешён.

Также `hasEmptyTextInput()` проверяет control-only input только для тех же двух
family, поэтому не обеспечивает ADR-011 Decision 5 для полного CTS surface.

**Impact:** для четырёх canonical family raw user-controlled text достигает
обеих handoff surfaces; redaction detector не является допустимой never-echo
границей.

**Remediation:** определять family и input через CTS metadata. Exact command
разрешать только для `input=none` либо optional input без текста; required и
optional с переданным text представлять локализованным non-executable descriptor
из protocol family. Распространить invalid/control-only validation и RU/EN
regressions на все перечисленные commands.

### F-002 — Medium (architecture/security/correctness) — mutation classification fail-open расходится с CTS surface

**Location:** `src/api/executors.ts:16-27,201-228`;
`src/api/agentDispatcher.ts:33-37`; `.project/command-transitions.json:134-169,188-207,222-249`.

`requiresWriteAccess()` — отдельный regex allowlist. Любая canonical CTS-команда
вне него становится read-only, а `writeInvocationPolicy()` возвращает успешную
`{ requiresWrite: false }`. В частности так классифицируются `SKILL INSTALL`,
`SKILL CREATE`, `GITHUB GENERATE TEMPLATES`, `HARNESS UPDATE APPLY`, `GIT COMMIT`,
`GIT PUSH` и `GIT PR`. CTS не является источником этой policy и неизвестная либо
неподдержанная mutation semantics не блокируется.

Текущий dispatcher по ADR-010 не spawn'ит процесс, поэтому automatic write не
происходит через штатный runtime path. Но обязательная pre-validation Mutation
policy уже даёт ложный success; кроме того, exported dormant `CliExecutor` с
`readIsolation` дойдёт до resolver/spawn для таких mutating operations как для
read-only.

**Impact:** заявленная STEP-009 pre-validation не соответствует full canonical
surface и future CTS command получит fail-open read-only classification.

**Remediation:** ввести исчерпывающую effect-policy, привязанную к CTS operation,
с fail-closed default; разделить filesystem write, remote mutation и unsupported
automatic execution. Добавить table-driven coverage всех CTS commands.

### F-003 — Medium (architecture/scope) — automatic lifecycle сохранён как dormant production code

**Location:** `src/api/executors.ts:169-249`; `src/api/contextBuilder.ts:31-83`;
`src/api/documentReloader.ts:22-60`; `src/git/gitHelper.ts:34-58`;
`src/api/types.ts:27-43`; `planning/tasks/STEP-009.md:76-80`;
`docs/adr/ADR-010-manual-agent-handoff-mvp.md:30-43`.

Runtime spawn не подтверждён: current path
`dispatchViaAgent()` → `HarnessAgentDispatcher` заканчивается manual fallback и
не создаёт `CliExecutor`, не вызывает context builder, reloader или git helper.

Но dormant implementation всё равно нарушает scope завершённого STEP-009:
production tree содержит executor resolution, stdin context transfer, `spawn`,
structured result, process-tree cancellation, context bundle и auto-reload,
хотя task относит их к Out of scope. ADR-010 допускает возврат automatic executor
только отдельным ADR и implementation STEP.

**Impact:** source и architecture contract расходятся; запрещённый lifecycle
можно вернуть одним wiring-изменением, а его presence в production и tests
создаёт ложное впечатление поддерживаемой capability.

**Remediation:** удалить dormant automatic implementation и owning tests из
manual-only product scope, сохранив историю в Git. Общие CTS/sanitization helpers
вынести из `executors.ts`; возвращать executor/context/reload только новым ADR и
STEP с требуемым evidence.

### F-004 — Medium (product contract/UX) — public cancellation/configuration surfaces обещают отсутствующий lifecycle

**Location:** `package.json:25-36,101-104,174-180`;
`src/commands/activation.ts:42-46`; `src/api/agentDispatcher.ts:13-26,45,55-57`;
`docs/adr/ADR-010-manual-agent-handoff-mvp.md:33-43`.

`harness.executables.codex` и `harness.executables.claude` публичны, но не
читаются production runtime и не нужны manual handoff. Публичные
`harness.cancelAgent`, Ctrl/Cmd+C и `harness.agent.running` обещают отмену agent
execution, хотя Extension Host не владеет manual process. `AbortController` в
manual dispatcher также не отменяет полезную длительную extension-owned работу:
после создания controller до fallback нет await, в который может вклиниться
cancel command.

**Impact:** пользователь видит configuration и cancellation guarantee для
lifecycle, запрещённого ADR-010, что вводит в заблуждение и нарушает manual-only
contract.

**Remediation:** удалить executable settings, cancel command, keybinding,
context key, controller и cancel interface из manual-only path. Если появится
реально длительная extension-owned pre-validation, проектировать отдельную
точно названную cancellation surface без обещания управления manual CLI.
