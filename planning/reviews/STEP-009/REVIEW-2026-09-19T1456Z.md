## Findings

### F-001 — High — mutating commands получают read-only режим без consent

**Location:** `src/api/executors.ts:9-16,106-119`,
`src/api/agentDispatcher.ts:41`, `tests/unit/api/executors.test.ts:15-19`.

`requiresWriteAccess()` ищет `INIT|ADD|IMPLEMENT|FIX|RUN|QUICK|RECONCILE` в
начале строки, тогда как Command layer передаёт `PLAN STEP-NNN`,
`IMPLEMENT STEP-NNN`, `REVIEW STEP-NNN` и т.д. В результате все реальные
команды не совпадают с regex. В частности PLAN и REVIEW получают Codex
`read-only` / Claude `plan` и не получают explicit write consent, хотя должны
создать durable artifact. Это нарушает ADR-006 и делает runtime-семантику
команд невыполнимой.

**Исправление:** заменить regex типизированной policy-классификацией всех
канонических команд; тестировать argv и consent для каждой mutating-команды.

### F-002 — High — prompt содержит legacy, неканоническую command form

**Location:** `src/commands/{init,addStep,plan,implement,review,fix,run,quickFix,reconcile}.ts`,
`src/api/contextBuilder.ts:60`, `.project/command-transitions.json`.

В prompt попадают `INIT PROJECT`, `PLAN STEP-1`, `REVIEW STEP-1`, хотя CTS
принимает `PROJECT INIT`, `STEP PLAN STEP-1`, `STEP REVIEW STEP-1`. Агент,
следующий обязательному command preflight, должен отклонить такие формы до
dispatch.

**Исправление:** привести inventory команд, prompt, consent и tests к одному
canonical syntax.

### F-003 — High — executable из PATH ошибочно считается доверенным

**Location:** `src/api/executors.ts:61-78,106-118`,
`src/git/gitHelper.ts:23-29`, `src/api/contextBuilder.ts:55-56`.

Первый executable с `X_OK`, чей `realpath` расположен вне workspace, считается
trusted. Writable ранний PATH entry позволяет подменить `git` до consent или
Codex/Claude и выполнить код с правами Extension Host; текущие tests сами
используют fake binary из temporary PATH.

**Исправление:** требовать configured/явно подтверждённый absolute executable
с проверяемой provenance, передавать минимальный environment и добавить
negative regression для writable PATH prefix.

### F-004 — High — allowlisted context не создаёт read boundary

**Location:** `src/api/contextBuilder.ts:55-71`,
`src/api/executors.ts:14-17,106-118`.

Builder ограничивает исходно переданные артефакты, но Codex получает
workspace-wide `read-only`, Claude — `Read`, а дочерний процесс наследует
environment. Инструкция в STEP/ADR способна попросить CLI прочитать `.env` или
другой невыбранный файл и передать его внешнему сервису.

**Исправление:** path-scoped read sandbox либо изолированный context bundle;
иначе отдельное informed consent/ADR для read boundary и исключение секретов.

### F-005 — Medium — workspace-wide write consent не fail-closed

**Location:** `src/parser/markdownParser.ts:322-340`,
`src/commands/stepPicker.ts:28-34`, `src/api/agentDispatcher.ts:74-82`.

Неполная Mutation policy превращается в пустые arrays с warning, который
теряется. Диалог показывает `-` и placeholder вместо выбранного STEP, но при
подтверждении может выдать workspace-wide write. Это противоречит ADR-006.

**Исправление:** блокировать write до spawn при неполной policy; показывать
exact canonical command, target STEP и validated Allowed paths.

### F-006 — Medium — диагностика и cancellation не выполняют safety contract

**Location:** `src/api/executors.ts:81-96,127-149`,
`src/api/agentDispatcher.ts:45-66,102-103`.

stdout/stderr накапливаются без ограничения и передаются в UI/Output без
redaction. При cancel escalation timer очищается при закрытии лидера, хотя
helper может продолжать работу; на Windows завершается только прямой child.

**Исправление:** bounded/redacted diagnostics и platform-specific termination
tree с подтверждённой bounded escalation; tests для surviving grandchild и
cancel во время retry.

### F-007 — Medium — пользовательский результат и fallback неполны

**Location:** `src/api/agentDispatcher.ts:32-60,85-103`,
`src/commands/baseCommand.ts:47-54`.

Output Channel не содержит summary, changed files и next command; при
недоступности обоих CLI пользователь видит generic failure вместо обязательного
manual fallback ADR-004.

**Исправление:** выводить безопасно нормализованный результат в `Harness` и
вернуть typed two-executor-unavailable/manual-mode action.

### F-008 — Medium — контекст и полный пользовательский цикл доказаны не полностью

**Location:** `src/api/contextBuilder.ts:14-17,57-70`,
`tests/unit/api/*.test.ts`, `tests/integration/commands.test.js:38-113`.

`relevantSections()` не выделяет `### REQ-NNN`, поэтому отправляет весь раздел
requirements. Tests не доказывают обязательные protocol/manifest/relevant REQ/
git artifacts, consent decline/write argv, pre-validation без spawn, runtime
recovery, retry exhaustion, single-flight, Output Channel и next-command UI.

**Исправление:** точный REQ section parser и contract-oriented unit/Extension
Host coverage перечисленных веток.
