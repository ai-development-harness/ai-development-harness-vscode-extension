## Findings

### F-001 — High (security) — automatic read-only invocation по-прежнему нарушает ADR-007

**Location:** `src/api/executors.ts:87-105`;
`docs/adr/ADR-007-agent-read-boundary.md:21-29`.

Для любой команды, которую `writeInvocationPolicy()` считает read-only,
executor создаёт temporary bundle и автоматически запускает настроенный Codex
или Claude. Но `cwd`, Codex `read-only` и Claude `plan + Read` не дают
подтверждённую OS-level path isolation. Комментарий на строках 87-89 прямо
утверждает обратное: будто bundle не позволяет инструкции прочитать соседний
`.env`.

**Scenario:** артефакт из bundle инструктирует CLI прочитать доступный процессу
файл вне bundle. Процесс видит filesystem пользователя и может передать
содержимое внешнему provider, хотя automatic invocation по ADR-007 в этом
случае запрещён.

**Impact:** нарушен Accepted ADR и security boundary; data minimization
ошибочно используется как разрешение на автоматический запуск внешнего
процесса.

**Fix direction:** ввести явную capability executor'а. Без доказанной
OS-level read isolation возвращать typed manual fallback до `spawn`; temporary
bundle не считать sandbox. Добавить regression с decoy secret вне bundle,
который также доказывает отсутствие child process.

### F-002 — High (security/correctness) — Ctrl+C может не остановить write-process в pre-spawn race

**Location:** `src/api/executors.ts:81-107`;
`src/api/agentDispatcher.ts:27-30`.

`AbortSignal` проверяется только в начале `invoke()`. Затем выполняются
асинхронные `realpath/access` и, для read-only, создание bundle. Обработчик
abort регистрируется лишь после `spawn` и присвоения `this.running`. Если
пользователь вызывает cancel в одном из этих `await`, dispatcher abort'ит
signal, но `CliExecutor.cancel()` ещё не видит процесса. После этого код всё
равно запускает CLI; listener, добавленный к уже aborted signal, не вызывается.

**Scenario:** пользователь подтверждает mutating-команду и сразу нажимает
Ctrl+C, пока разрешается configured executable. Agent стартует после отмены с
workspace-wide write и продолжает менять файлы до собственного завершения.
Лишь обработчик `close` позже классифицирует результат как cancelled.

**Impact:** UI принимает отмену, но работа и mutations продолжаются; acceptance
«прервать без порчи состояния проекта» не выполнен.

**Fix direction:** регистрировать abort до первого `await`, повторно проверять
signal после каждого pre-spawn await и непосредственно до/после `spawn`; child,
созданный одновременно с abort, немедленно завершать. Добавить детерминированный
regression с задержанным executable resolution и проверкой отсутствия spawn /
живого descendant.

### F-003 — Medium (reliability) — одна длинная Codex JSONL-строка не ограничена по памяти

**Location:** `src/api/executors.ts:108-111`.

Общий stdout больше не обрезается, но незавершённая строка накапливается через
`codexLines += chunk` без лимита. Ограничения существуют для stderr и полного
Claude response, но не для одного Codex event/terminal payload.

**Scenario:** tool/agent возвращает много мегабайт текста внутри одного JSON
event без перевода строки. Extension Host не может передать event parser'у,
пока память продолжает расти.

**Impact:** memory exhaustion или падение Extension Host вместо runtime
recovery REQ-005.

**Fix direction:** ограничить размер незавершённой JSONL-строки и terminal
payload; при превышении завершать process с typed `too-large`. Добавить тест на
oversized single-line event, а не только на много коротких progress events.

### F-004 — Medium (correctness) — Output Channel не получает progress агента

**Location:** `src/api/executors.ts:110-121`;
`src/api/agentDispatcher.ts:45-80`; REQ-005.

Codex JSONL разбирается потоково, но progress/tool events отбрасываются.
Dispatcher публикует только собственные stage markers и финальный result;
Claude output обрабатывается целиком после `close`. Во время долгого запуска
пользователь после `[executor]` не видит никакого живого progress.

**Scenario:** IMPLEMENT/FIX несколько минут выполняет tool calls. Output Channel
открыт, но фактическая активность агента до завершения невидима.

**Impact:** прямое требование REQ-005 «отображает прогресс и результат» не
выполнено; предыдущий F-002 из report `1541Z` не закрыт.

**Fix direction:** добавить bounded/redacted progress callback из executor layer
в dispatcher и наблюдаемое сообщение до final result. Для Claude либо явно
определить доступный lifecycle progress в рамках ADR-004, либо принять новый ADR
для streaming transport. Добавить unit/Extension Host assertion на progress до
завершения процесса.

### F-005 — Medium (compatibility/data minimization) — на Windows в prompt попадает весь SPEC

**Location:** `src/api/contextBuilder.ts:59-71`;
`tests/unit/api/contextBuilder.test.ts:27-41`.

Requirements исключается из полного списка через
`item.path.endsWith(manifest.sources.requirements)`. На Windows абсолютный путь
использует `\\`, а manifest path — `/`, поэтому comparison ложно: builder
добавляет полный `SPEC.md`, затем ещё раз relevant REQ section.

**Scenario:** Windows-пользователь запускает STEP с одним связанным REQ. Agent
получает все требования проекта вместо только релевантного раздела.

**Impact:** нарушены planned relevant-context boundary и data minimization;
platform-independent tests не выявляют дефект.

**Fix direction:** исключать requirements через уже вычисленный exact resolved
`requirementsPath`, а не suffix с разными separators. Добавить Windows-path
regression и assertion, что соседний REQ отсутствует в prompt.

### F-006 — Medium (verification) — security и user-visible acceptance paths остаются недоказанными

**Location:** `tests/unit/api/agentDispatcher.test.ts:18-63`;
`tests/integration/commands.test.js:66-143`;
`tests/unit/api/contextBuilder.test.ts:27-41`.

Unit lifecycle использует несуществующую read-only команду `STEP AUDIT` и не
проверяет write consent. Extension Host tests умеют только принять toast: нет
сценария decline/cancel до spawn и assertions exact canonical command + Allowed
paths. Cancel scenario лишь ждёт Promise, но не доказывает отсутствие живого
descendant/partial result. Ни unit-, ни integration-тесты не наблюдают строки
Output Channel, progress, сохранение dirty document и полный состав context
(protocol/manifest/exact REQ/git).

**Impact:** обязательная Verification заявляет больше, чем доказано, а
регрессии consent, observability, cancel и context boundary проходят зелёные
gates.

**Fix direction:** добавить contract-oriented tests для decline/cancel consent
без spawn, содержимого consent, pre-spawn cancel race/process tree, Output
Channel и progress, exact context/no соседнего REQ, dirty reload и graceful
reload failure.
