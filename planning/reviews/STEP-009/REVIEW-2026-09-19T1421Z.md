## Findings

### F-001 — High — PLAN и REVIEW получают read-only permissions

**Location:** `src/api/executors.ts:9-16,106-119`;
`tests/unit/api/executors.test.ts:15-19`.

`requiresWriteAccess()` не классифицирует `PLAN` и `REVIEW` как mutating,
хотя они пишут Implementation plan и immutable review report. Поэтому для них
не показывается consent ADR-006, Codex получает `read-only`, а Claude `plan`.
Команды не могут выполнить собственную runtime-семантику.

**Исправление:** заменить строковую проверку на полную семантическую policy
классификацию всех mutating commands и покрыть argv/consent каждой команды.

### F-002 — High — UI передаёт агенту legacy, неканонические команды

**Location:** `src/commands/{init,addStep,plan,implement,review,fix,run,quickFix,reconcile}.ts`;
`src/api/contextBuilder.ts:60`; `.project/command-transitions.json:18-90`.

В context/prompt попадают `INIT PROJECT`, `PLAN STEP-NNN` и аналогичные
legacy forms вместо требуемых `PROJECT INIT`, `STEP PLAN STEP-NNN` и
`STEP REVIEW STEP-NNN`. Агент, обязанный применить CTS, не сможет надёжно
валидировать и маршрутизировать такую команду.

**Исправление:** привести command registration, dispatch context и prompt к
единственному canonical syntax и добавить integration regression cases.

### F-003 — High — executable из PATH ошибочно считается доверенным

**Location:** `src/api/executors.ts:61-78,106-118`;
`src/git/gitHelper.ts:23-29`; `src/api/agentDispatcher.ts:34-42`.

Любой первый executable из наследуемого `PATH` вне workspace принимается как
trusted; `git` запускается до consent. Writable ранний PATH entry позволяет
подменить `git`/CLI, выполнить код от имени Extension Host и получить prompt
или environment.

**Исправление:** требовать configured absolute executable либо проверяемую
trusted provenance, санитизировать environment и добавить negative tests для
writable PATH entry.

### F-004 — High — read-only режим не ограничивает чтение allowlisted context

**Location:** `src/api/contextBuilder.ts:19-23,29-70`;
`src/api/executors.ts:14-17,106-118`.

Context builder читает allowlisted артефакты, но Codex получает workspace-wide
`read-only`, а Claude — unrestricted `Read`. Prompt injection из выбранного
STEP/ADR может заставить CLI прочесть `.env` или иной невыбранный файл и
передать данные внешней модели.

**Исправление:** ввести path-scoped read sandbox/copy-only context либо
явный informed consent на workspace-read с ADR reconciliation; добавить test
с decoy secret вне allowlist.

### F-005 — Medium — consent ADR-006 не fail-closed и не привязан к target

**Location:** `src/parser/markdownParser.ts:322-340`;
`src/commands/stepPicker.ts:30-34`; `src/api/agentDispatcher.ts:74-82`.

Warnings о неполной Mutation policy теряются, пустая policy всё равно ведёт к
workspace-wide write consent. Диалог показывает placeholder, а не exact
canonical command с выбранным STEP и валидированными Allowed paths.

**Исправление:** перед write invocation отклонять неполную policy до spawn и
показывать exact command/target и parsed Allowed paths.

### F-006 — Medium — в prompt попадают нерелевантные REQ

**Location:** `src/api/contextBuilder.ts:14-17,68-70`;
`docs/requirements/SPEC.md:25`.

`relevantSections()` распознаёт только `#`/`##`, тогда как REQ имеют heading
`###`. При выборе REQ-005 в prompt попадает весь раздел требований.

**Исправление:** извлекать точные границы `### REQ-NNN` parser-ом и добавить
fixture с несколькими REQ и отрицательной проверкой.

### F-007 — Medium — diagnostics и cancellation не удовлетворяют safety contract

**Location:** `src/api/executors.ts:35-48,81-96,127-149`;
`src/api/agentDispatcher.ts:45-66,102-103`.

stderr/error text не ограничен и не redact-ится перед Output/UI; CLI может
echo prompt/token и исчерпать память. Cancel не доказывает остановку всего
process tree: на Windows завершается только child, а POSIX escalation может
сниматься после закрытия лидера при живом helper process.

**Исправление:** ограничить и redact-ить external output; реализовать
platform-specific tree termination с подтверждённым завершением и tests для
surviving grandchild и cancel во время retry.

### F-008 — Medium — обязательная user-visible verification неполна

**Location:** `tests/integration/commands.test.js:38-113`;
`tests/unit/api/{agentDispatcher,contextBuilder,executors}.test.ts`;
`planning/tasks/STEP-009.md:65-68,168-172`.

Extension Host success проверяет stdin и active editor, но не Output Channel,
changed files, next command, structured result, agent error/retry или
two-executor unavailable/manual fallback. Нет coverage consent, guard,
retry-cancel и EPIPE. Обязательные real Codex happy-path и Ctrl+C/SIGTERM
manual checks по-прежнему не доказаны из-за DNS `api.openai.com`.

**Исправление:** добавить перечисленные contract tests. После устранения
локальных defects сохранить manual external evidence; mock CLI его не заменяет.
